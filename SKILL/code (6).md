# Skill: 先设计后编码

## 触发条件
需求涉及新建文件 ≥2 个、或新增核心功能模块时。

## 流程
1. 先输出设计稿（≤30 行）：
   - 数据流图（输入→处理→输出，箭头一行）
   - 模块职责表（模块名 | 职责 | 依赖）
   - 关键接口签名（只签名不实现）
2. 标注风险点（线程边界、状态变更、外部依赖）
3. 用户确认后才写实现。

## 设计原则（写码时持续生效）
- 单一职责：一个类一个变化理由；UI / 业务 / IO 三层分离
- 依赖方向：view → worker → service，禁止反向
- 显式优于隐式：魔法数字提常量，状态用枚举
- 跨模块通信用信号总线，禁止界面互相 import
