# Skill: 省 Token 输出规范

## 触发条件
所有代码类回答。

## 规则
1. 只输出「本次修改涉及」的代码；未变的函数/类省略并用精确锚点标注：
   `# ...其余不变，仅修改 XWidget.onSend 中 42-58 行`
2. 大改动给完整文件；小改动给 diff 式片段 + 明确插入位置（"在 __init__ 末尾、connect 之前"）。
3. 解释文字：先结论后细节，每段 ≤3 句；代码注释只标注"为什么"，不注释"是什么"。
4. 不重复用户已知信息；不输出客套话、总结性套话。
5. 多方案对比用表格，禁止方案 ABC 各写一大段散文。
6. 已在上下文中出现过的代码，引用而非重贴。

## 长任务模式
大型生成先输出「文件清单 + 每文件职责一句话」等用户确认，再逐文件生成 —— 避免方向错了浪费整轮 token。
