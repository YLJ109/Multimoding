# Skill: 系统化排错协议

## 触发条件
用户提供报错信息或异常行为时。

## 铁律
1. 先读完整 traceback，定位最深的一帧「用户代码」，禁止跳过 traceback 直接给"常见原因"。
2. 修改前必须先陈述「根因假设」一句话，再给修改。禁止无假设的 shotgun 修改（一次改 5 处碰运气）。
3. 一次只改一个变量；改后给出「验证方法」。
4. 若信息不足，列出「需要用户提供的信息清单」（版本、完整报错、复现步骤），最多 3 项。
5. 修复后主动检查同类隐患（"你的另外 2 处 XX 也存在同样问题"）。

## 反例
- ❌ "可能是网络问题，你重启试试"
- ❌ 一次性重写整个文件来修一个 typo
