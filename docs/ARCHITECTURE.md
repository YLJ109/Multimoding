# DanceMirror 系统架构

## 1. 产品边界

DanceMirror 是面向比赛演示和实际训练的 PyQt6 多模态舞蹈训练系统。当前实现遵循以下不可破坏的边界：

- 学习舞蹈页面的大画面只显示一个 3D 机器人。参考视频中的人物通过动作包驱动这个机器人，不生成第二个 3D 角色。
- 摄像头前的人始终只显示在左上角的二维叠加层中，包括人体骨架、人脸关键点和双手 21 点骨架；不生成用户 3D 人物，也不运行 SMPL-X。
- 训练音乐来自舞蹈视频原声。视频原声可用时默认直接使用，不强制用户额外导入音乐。
- 云端 LLM、ASR 和 TTS 都是增强能力。断网、超时、密钥无效或接口不兼容时，本地评分、动作回放、训练记录和基础提醒仍可继续。
- 默认角色是项目内可再分发的成人比例赛博人形 `dance_robot_cyber.glb`（Quaternius，CC0 1.0）。项目不内置蜘蛛侠、奥特曼等受保护 IP；用户只能导入自己拥有授权的本地 GLB。
- 目标设备为 RTX 3060 Laptop 6GB。任何时刻不并行运行两个高成本 3D 角色或多个视觉大模型。

## 2. 分层结构

```text
src/dance_mirror/
  app.py                  QApplication、日志、默认深色主题和主窗口启动
  config.py               AppPaths 与 QSettings 配置门面
  capture/                摄像头和视频输入
  pose2d/                 YOLO Pose 二维关键点边界
  pose3d/                 保守深度提升、根运动和质量证据
  multimodal/             MediaPipe 人脸、手势、摄像头预览与就位判断
  privacy/                多人画面保护
  motion/                 归一化、比较空间、同步、特征、评分和重定向
  session/                显式舞蹈会话状态机
  command/                本地命令解析、安全分级、队列和参数验证
  coaching/               纠错策略、本地/云端 TTS、训练摘要和提示词
  renderer/               单机器人 Three.js 场景、角色目录和 Python/JS 桥
  services/               动作包分析、训练统计等领域服务
  storage/                版本化动作包与 SQLite 训练历史
  workers/                QThread Worker、云端调用和统一生命周期注册表
  view/                   PyQt6 页面、独立训练窗口、卡片库、设置和主题
```

`view/` 只负责交互展示，`main_window.py` 负责装配页面、连接信号和管理会话。算法服务、网络访问、模型推理、数据库和文件 IO 不应回到 UI 线程执行。

## 3. 启动与主题

1. `app.py` 创建 `QApplication`。
2. 启动阶段先应用深色主题，避免主窗口出现浅色闪屏。
3. `MainWindow` 读取 `appearance/theme`。键不存在时使用 `dark`；用户已经保存过 `light` 时尊重用户选择。
4. 主题切换同时更新 Qt 样式表、历史图表、动作包卡片、摄像头叠加层和 Three.js HUD。
5. F11 与设置页共享同一个全屏切换入口。

## 4. 舞蹈包流水线

### 4.1 导入与转换

```text
视频/音乐 -> 元数据预检 -> YOLO Pose 2D -> 时间对齐 -> 平滑
         -> 保守 3D 提升 -> BPM/节拍/质量报告 -> 原声提取
         -> 版本化 *.dmotion.json 舞蹈包
```

转换过程在 Worker 中执行。每一步都应能报告进度、失败原因和取消状态。临时文件只能在成功提交后进入舞蹈包库，失败时清理。

### 4.2 舞蹈包库

封面统一为 16:9 海报卡片，靠左排列。卡片展示标题、时长、BPM、难度、质量等级、许可、音乐状态和最近训练。支持搜索、筛选、排序、重命名、删除、更换海报、原声重提取和详情窗口。

### 4.3 数据安全

动作包目录必须防止路径穿越。删除和重命名只允许操作库根目录内的已登记包。导入的原始视频、音乐和 3D 角色分别校验扩展名、文件大小、许可证声明和可解析性。

## 5. 学习舞蹈会话

### 5.1 状态机

会话状态统一为：

```text
Idle -> Preflight -> CameraWarmup -> Countdown -> Playing
     -> Paused -> Playing
     -> Finalizing -> Settled -> Closed
```

按钮、定时器、Worker 回调和窗口关闭都必须通过 `DanceSessionStateMachine` 转换。非法转换必须被拒绝并记录，不能依靠多个布尔变量拼接状态。

### 5.2 页面边界

- 用户从资源库选择舞蹈包后打开独立 `DanceSessionWindow`。
- 会话窗口不显示“返回资源库”按钮，关闭窗口即结束当前会话并回到主窗口。
- 主画面始终只有一个 3D 机器人。
- 左上角摄像头区域显示二维骨架、人脸和双手。
- 倒计时必须在全身就位、双手可见且主要关节达到最低置信度后触发。
- OK 手势需要保持规定时长，防止误触。
- 训练结束结算页提供总分、部位得分、问题排行、复训建议和导出入口，关闭即结束独立窗口。

### 5.3 音乐主时钟

训练时钟以视频原声或动作包音乐为基准，画面回放、评分窗口、提示音和语音纠错向同一时钟对齐。用户补偿值、捕获延迟和平滑参数由设置页控制。不得让音频和动作播放器各自维护独立时间轴。

## 6. 机器人指挥中心

指挥中心包含三种动作来源：

1. 实时摄像头模仿。
2. 自然语言命令。
3. 舞蹈包回放。

三种来源统一进入动作仲裁器。高优先级安全命令、紧急停止和本地固定命令不能被云端计划绕过。实时模仿只把二维姿态重定向到 3D 机器人；用户本身不变成 3D 人物。

角色、皮肤和场景是三个独立维度。角色切换可以更换 GLB，皮肤只修改材质或预设角色外观，场景只修改灯光、地面和背景。切换时必须释放旧资源并遵守显存预算。

## 7. Worker 与线程规则

### 7.1 线程边界

- UI 线程只处理 QWidget、QPixmap、QWebEngineView、信号连接和轻量状态更新。
- 摄像头读取、YOLO 推理、MediaPipe、视频解析、网络、SQLite 和文件 IO 在 Worker 线程执行。
- Worker 通过信号回传不可变数据或纯 Python 对象，不修改 QWidget。
- 每帧数据不得无界堆积。消费者落后时应丢弃旧预览帧，但关键评分帧按策略处理。

### 7.2 WorkerRegistry

所有长生命周期 Worker 由 `WorkerRegistry` 统一登记，至少记录名称、控制器、所属会话、资源类型和停止状态。关闭顺序为：

1. 拒绝新任务。
2. 取消当前会话。
3. 停止摄像头和视觉 Worker。
4. 停止网络 Worker。
5. 停止音频、数据库和文件 Worker。
6. 等待线程退出。
7. 记录超时线程并释放设备句柄。

控制器只能停止一次。`MainWindow`、独立会话窗口和注册表不得重复执行破坏性清理。

## 8. 云端能力与降级

支持的云端能力都采用 OpenAI-compatible 接口，但提供商、Base URL、模型、超时、语音和密钥由设置页配置。密钥只保存在当前进程内存，不写入 QSettings、日志、数据库或动作包。

| 能力 | 典型请求 | 本地降级 |
|---|---|---|
| LLM | JSON 训练摘要、复杂语言计划 | 本地规则评分、模板总结、固定命令 |
| ASR | 语音转文字 | 本地语音命令词和高置信度固定短语 |
| TTS | 实时语音纠错 | Windows SAPI 本地语音，必要时只显示文字 |

所有云端返回都要经过结构校验和本地白名单验证。LLM 不能直接执行命令、修改文件、选择未验证模型路径或决定安全权限。

设置页提供 LLM、ASR、TTS 独立连通性测试。测试在 Worker 中运行，不阻塞 UI，并明确区分 DNS、认证、超时、响应格式和服务商不支持等情况。

## 9. 数据目录

```text
%LOCALAPPDATA%\DanceMirror\
  logs\                运行日志
  data\                SQLite 历史数据库
  motion_packages\     版本化舞蹈包
  recordings\          用户主动开启的训练录像
  models\              YOLO 等模型权重
  characters\          用户导入且已授权的 GLB
```

`DANCE_MIRROR_HOME` 可以整体覆盖根目录。所有路径从 `AppPaths` 获取，禁止依赖当前工作目录的隐式相对路径。

## 10. 隐私

- 默认不保存摄像头录像，必须由用户主动开启。
- 默认启用其他人物的隐私遮蔽。
- 云端只接收结构化分数、部位统计和必要文本，不上传连续原始视频。
- 人脸关键点只用于就位、可见性和表情辅助，不用于身份识别或权限判断。
- 日志不得记录 API Key、原始语音、完整视频路径中的敏感信息和用户身份。

## 11. 6GB 显存策略

- 同一时刻只保留一个 YOLO Pose 实例。
- 参考视频转换和实时摄像头推理不同时运行高负载 GPU 任务。
- 默认摄像头 720p、实时目标 15 FPS、渲染目标在 45 到 60 FPS 之间按设备能力调整。
- 低功耗模式降低分辨率、FPS、阴影、抗锯齿和材质尺寸。
- 显存不足时依次降级：分辨率、推理 FPS、YOLO `imgsz`、场景质量、角色材质、ONNX/TensorRT。
- 不允许在同一设备上并行运行本地大语言模型和高精度 SMPL-X。

## 12. 测试与验收

自动测试至少覆盖：

- 会话状态转换和非法状态。
- WorkerRegistry 生命周期、停止和超时。
- 设置校验、回滚和摄像头切换。
- 云端超时、空响应、错误 JSON 和本地降级。
- 舞蹈包转换、路径安全、取消和临时文件清理。
- 单机器人场景、二维用户叠加和双手骨架契约。
- 默认深色、显式浅色和 3D HUD 主题同步。
- SQLite 历史统计、趋势、薄弱部位和 CSV 导出。

发布前还要在目标机器执行 WebEngine 3D 烟雾测试、真实摄像头就位测试、10 分钟连续训练测试和断网比赛演练。性能数字必须来自目标机器实测，不能只依据理论估算。
