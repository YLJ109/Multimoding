# DanceMirror 项目全面升级方案 V11

## 0. 文档定位

本方案基于当前代码、测试、文档和运行时的全面扫描结果编写，不改变已经确认的产品边界：

- 学习舞蹈页主画面只有一个 3D 机器人。
- 摄像头前的人始终只以左上角二维骨架、人脸和双手叠加呈现，不生成用户 3D 人物。
- 音乐来自舞蹈视频原声，不强制额外导入音乐。
- 角色资源默认使用 CC0 或明确许可资源，不内置蜘蛛侠、奥特曼等受保护 IP；用户只能导入自己有权使用的本地 GLB。
- 本地核心训练链路必须可用，云端 LLM、ASR、TTS 只作为增强能力。
- 目标设备为 RTX 3060 Laptop 6GB，低端设备优先保证稳定、可操作和可降级。

本方案不是简单的功能清单，而是按“稳定底座 -> 核心体验 -> 游戏化与 AI -> 视觉精修”的顺序推进，避免在现有主窗口上继续叠加功能导致状态串线和线程风险。

## 1. 当前基线与扫描结论

### 1.1 已验证基线

- `58` 项自动化测试全部通过。
- `61` 项自动化测试全部通过。
- `ruff` 静态检查通过。
- `compileall` 通过。
- WebEngine 3D 烟雾测试通过。
- 渲染状态确认：单画布、单角色、机器人主骨骼 `13` 根、手指骨骼 `16` 根。
- 鼠标交互已具备左键旋转、右键或中键平移、滚轮缩放、双击复位。
- 舞蹈包 V2、SQLite 历史、YOLO Pose、MediaPipe 手势与人脸、云端模型预设均已有实现。

### 1.2 主要风险

| 等级 | 问题 | 影响 |
|---|---|---|
| P0 | `main_window.py` 同时承担 UI、会话状态机、线程生命周期、音乐时钟、命令队列、云端、设置和关闭清理 | 新增功能容易造成回归、死锁和状态污染 |
| P0 | 会话状态由多个布尔量组合表示 | 暂停、倒计时、结算、关闭之间存在非法状态空间 |
| P0 | 大量 Worker 由分散字段管理 | 关闭、换摄像头、切换页面时可能出现线程未退或资源未释放 |
| P0 | 设置保存后立即应用，缺少预校验和回滚 | 错误模型路径、不可用摄像头或云端配置可能影响当前会话 |
| P1 | 历史和报告页面只有基础表格 | 缺少趋势、薄弱部位、复训入口和报告导出 |
| P1 | 舞蹈包详情使用普通消息框 | 缺少资产抽屉、音频试听、质量解释、许可信息和预览 |
| P1 | 深色主题虽已存在，但 Canvas 和局部样式仍硬编码 | 浅色和深色页面无法完全一致 |
| P1 | 旧首页和旧训练页仍存在但与主导航边界不一致 | 增加维护成本，也让产品信息架构不清晰 |
| P1 | 云端缺少统一连通性测试和降级说明 | 用户填写密钥后无法快速判断哪项能力真正可用 |
| P2 | 游戏化、排行榜、复训回放和 AI 教练仍较薄 | 演示完整度不足，长期使用价值有限 |

### 1.3 结论

当前项目已经从原型进入“可持续产品化”阶段。下一阶段不应再以增加孤立按钮为主要目标，而应把稳定性、会话生命周期、资产工作流和训练分析做成完整闭环。

## 2. 升级原则

1. 先拆状态和生命周期，再做新功能。
2. 先保证本地离线可用，再增强云端能力。
3. 所有云能力都必须有本地降级路径。
4. 任何一个新页面都必须同时具备浅色、深色、全屏、空状态、加载、错误和恢复状态。
5. 6GB 显存是硬约束，任何时候都不能同时运行两个 3D 角色或多个高成本视觉模型。
6. 所有用户数据、模型、视频、音乐和角色资源都要有来源、许可和删除策略。
7. 所有实时能力都要有明确的延迟、FPS、显存和 CPU 预算。

## 3. 目标架构

### 3.1 MainWindow 拆分

建议将当前主窗口拆成以下边界：

- `AppShell`：窗口、导航、全屏、主题和全局状态栏。
- `SessionCoordinator`：唯一的训练会话状态机。
- `WorkerRegistry`：统一拥有、停止、等待和回收所有 Worker。
- `SettingsCoordinator`：设置快照、脏状态、校验、预应用和回滚。
- `MediaCoordinator`：视频原声、播放器、速度、暂停和音乐时钟。
- `CommandCoordinator`：本地命令、云计划、优先级队列、取消和安全回退。
- `CloudCapabilityService`：LLM、ASR、TTS 分能力测试和预设解析。
- `TrainingAnalyticsService`：分数、部位、问题排行、趋势和复训建议。
- `AssetCatalogService`：舞蹈包、角色、场景和许可元数据。
- `UiDesignSystem`：颜色、间距、图标、控件变体和主题语义变量。

`MainWindow` 最终只负责装配和页面切换，不再保存业务状态。

### 3.2 会话状态机

训练会话必须有单一状态机：

`Idle -> Preflight -> CameraWarmup -> Countdown -> Playing -> Paused -> Finalizing -> Settled -> Closed`

每个状态需要定义：

- 允许进入的状态。
- 允许执行的命令。
- 超时时间和超时动作。
- 需要启动或停止的 Worker。
- 需要显示或隐藏的控件。
- 是否允许关闭窗口。
- 失败后回退到哪个状态。

任何非法转换都必须被记录并拒绝，不能依靠多个布尔变量临时判断。

### 3.3 WorkerRegistry

每个 Worker 统一带有：

- 唯一名称和所属会话。
- 取消令牌。
- 启动、停止、超时和错误回调。
- 运行时长、最近心跳和错误码。
- 资源类型：摄像头、模型、网络、数据库、文件或渲染。
- 关闭优先级。

关闭流程统一为：

1. 停止新任务。
2. 取消会话。
3. 停止摄像头和模型 Worker。
4. 停止网络 Worker。
5. 停止音频和渲染。
6. 等待线程退出。
7. 回收临时文件和设备句柄。
8. 记录未能按时退出的 Worker。

## 4. P0 稳定性和架构升级

### 4.1 会话生命周期

- 增加 `SessionToken`，所有异步回调都必须校验 token，防止旧会话更新新页面。
- 增加倒计时取消、摄像头初始化超时、模型加载超时和结算超时。
- 关闭独立训练窗口时，必须完成暂停、停止、结算、Worker 回收和音乐停止。
- 训练异常不能只显示消息框，还要保存错误上下文和可恢复建议。

验收标准：

- 连续开始、暂停、恢复、停止、关闭 `20` 次不出现状态串线。
- 关闭窗口后没有摄像头占用、音频继续播放或后台线程残留。
- 云端超时不会阻塞本地训练。

### 4.2 设置系统

- 设置分为“基础”和“高级”，支持搜索。
- 页面维护草稿状态，只有点击保存才正式生效。
- 离开设置页时如有未保存修改，给出保存、放弃或继续编辑选择。
- 云端 LLM、ASR、TTS 分别提供 `Test Connection`。
- 摄像头提供预览、分辨率、设备名称和占用检测。
- 模型路径、GLB 文件、摄像头编号、云端 URL、超时和时间同步都必须在应用前校验。
- 设置应用失败时回滚到上一份有效快照。
- API Key 只保存在当前进程内存，不写入 QSettings、日志、数据库或动作包。

### 4.3 文档校正

- `ARCHITECTURE.md` 必须更新为当前“单 3D 机器人 + 左上角二维用户骨架”的真实边界。
- 删除或标记过时的左右双视角、用户 3D 重建描述。
- 补充 WorkerRegistry、SessionCoordinator 和云端降级策略。
- 增加数据目录、清理策略、许可和隐私说明。

### 4.4 测试门禁

新增测试：

- 会话状态转换测试。
- 窗口关闭和 Worker 超时测试。
- 摄像头切换与重新获取测试。
- 设置回滚和无效配置测试。
- 云端超时、空响应和不支持模态测试。
- 舞蹈包转换取消和临时文件清理测试。
- 浅色、深色和全屏烟雾测试。
- 长时间运行测试：至少连续运行 `60` 分钟，包含多次暂停、恢复和摄像头切换。

## 5. P1 核心功能升级

### 5.1 舞蹈包库 2.0

- 卡片从“功能按钮集合”升级为“资产卡片”。
- 卡片继续靠左排列，支持响应式列数和列表模式。
- 海报统一 16:9，显示标题、时长、BPM、难度、质量、许可、最近训练和完成率。
- 增加搜索、标签筛选、难度筛选、BPM 筛选、质量筛选和排序。
- 详情改为右侧抽屉或独立模态框，包含：
  - 动态预览。
  - 原视频来源。
  - 帧数、FPS、时长和动作质量。
  - 音乐标题和许可。
  - 薄弱片段入口。
  - 最近训练成绩。
  - 删除、重命名、换海报、重新提取原声。
- 支持拖拽导入视频。
- 支持批量重命名和回收站恢复。
- 增加空状态、损坏包状态和缺少音乐状态。

### 5.2 视频转舞蹈包工作流

- 将转换过程拆成可观察步骤：解码、检测、平滑、3D 提升、音乐提取、海报选择、质量控制、打包。
- 每一步显示进度、预计剩余时间、可取消状态和错误原因。
- 转换前可选择“快速、平衡、质量优先”三档。
- 自动检测 BPM 和节拍，失败时回退到手动值。
- 生成质量报告，说明遮挡、低置信度、快速旋转和左右不确定性。
- 转换完成后的预览只显示标准 3D 机器人，不显示用户 3D。

### 5.3 角色与场景工作室

- 角色卡片包含缩略图、作者、许可、体积、骨骼兼容性和安装状态。
- 支持本地 GLB 导入、体积检查、骨骼检查、手掌和手指骨骼检查。
- 对没有手指骨骼的模型自动叠加 21 点手掌骨架，但必须明确标记为“视觉叠加，不是原生手指”。
- 支持角色缩放、旋转、地面高度和朝向校准。
- 支持角色资源删除和缓存清理。
- 默认提供 CC0 或明确许可的机器人、简约人体和抽象模型。
- 不内置任何受保护 IP；受保护角色只能由用户导入已授权文件。
- 场景提供训练舞台、宿舍、霓虹夜场、极简摄影棚等预设。
- 场景质量分为低、中、高三档，以保证 6GB 设备可运行。

### 5.4 训练会话 2.0

- 主画面只有一个 3D 机器人，左上角摄像头叠加可切换大小和收起。
- 3D 区域增加轻量工具条：视角复位、显示骨架、显示人体、显示层切换、性能 HUD。
- HUD 增加当前分数、连击、准确度、覆盖率、目标动作、延迟、置信度和薄弱部位热区。
- 时间轴显示节拍、错误密度、当前播放位置和可复训片段。
- 播放速度和音乐位置始终同步。
- 倒计时只允许在全人、双手和主要关节准备好后开始。
- 结算页面包含总分、部位分数、错误排行、建议动作、复训按钮、报告导出和关闭窗口。
- 关闭结算窗口后不跳转复杂页面，直接结束当前独立窗口。

### 5.5 训练历史 2.0

- 首页改为训练分析面板，而不是只有表格。
- 增加总览卡：训练次数、累计时长、平均分、最近提升。
- 增加趋势折线图：总分、准确度、手部、头部和覆盖率。
- 增加部位雷达图或条形图。
- 增加问题排行：最常见错误、最长持续错误、最需要复训片段。
- 增加最近训练对比和最佳表现标记。
- 支持按舞蹈包、时间和分数筛选。
- 支持从历史记录一键返回对应舞蹈包并复训薄弱片段。
- 支持导出本地报告：HTML、PDF 或 CSV。
- 训练录像和截图必须由用户主动开启，显示存储位置和清理入口。

### 5.6 云端能力中心

- 保留国内模型预设：DeepSeek、千问、Kimi、智谱、SiliconFlow、MiniMax、混元、讯飞星火、千帆、零一万物、百川、MiMo、OpenRouter。
- 每个预设显示实际支持的能力：文本、图像理解、语音识别、语音合成。
- 不支持的模态必须在界面明确标记“不可用”或“回退本地”。
- 每个能力独立填写密钥，也允许复用同一个密钥。
- `Test Connection` 返回延迟、状态码、模型可用性和错误类型。
- 云端只接收结构化训练摘要，不接收连续视频帧。
- 云端报告必须注明“基于本地结构化分数”，不得编造动作、伤病、身份或情绪。
- ASR 失败时保留文字命令。
- TTS 失败时回退 Windows 本地语音或静音，不阻塞训练。

### 5.7 摄像头诊断

- 下拉框显示编号和名称。
- 提供刷新、预览、分辨率、实际 FPS、占用和打开失败原因。
- 支持摄像头热切换。
- 切换前先释放旧设备，再打开新设备；失败时回滚到上一个可用设备。
- 摄像头无法打开时，训练页必须显示可操作错误，而不是只进入等待。

## 6. P2 高级功能与游戏化

### 6.1 游戏化进度

- 每支舞蹈增加目标分、三星评级、连击目标、准确度目标和完成次数。
- 增加每日挑战、周目标、连续训练天数和个人最佳。
- 增加舞者称号、徽章和可解锁皮肤。
- 排行榜只保存在本地，避免隐私和作弊问题；如需在线排名，必须单独设计匿名和授权流程。

### 6.2 AI 教练 2.0

- 使用结构化分数、错误持续时长、部位分数和节拍统计作为唯一事实来源。
- 生成训练前计划、训练中提示和训练后总结。
- 每次只给一个最高价值纠错提示，避免语音刷屏。
- 报告结构固定：最大问题、证据、下一次练习动作、安全提醒。
- 支持多种教练风格：严格、鼓励、简洁、比赛模式。
- 所有提示模板必须版本化、可测试、可回退。

### 6.3 机器人指挥中心 2.0

- 主区域保持 3D 场景，右侧为命令控制台。
- 显示实时转写、意图、参数、置信度、优先级、执行状态和失败原因。
- 支持语音、文字和快捷按钮三种入口。
- 危险命令永远走本地快速通道，不经过云端。
- 复杂命令由云端生成 JSON 计划，但必须在本地白名单、参数范围和动作包 ID 三重校验。
- 支持命令队列的可视化、取消、重试和上下文帮助。
- 支持“跳某支舞、暂停、继续、变速、移动、挥手、换皮肤、换场景、切换视角”等可执行动作。
- 机器人动作与语音确认必须可同步，也可单独关闭。

### 6.4 多模态评价 2.0

- 人体骨架：四肢、躯干、头部。
- 手掌：左右手 21 点、手势、开合度和同步度。
- 人脸：存在性、遮挡、表情和可见度，不做身份识别。
- 动作质量：帧置信度、遮挡、快速旋转和左右不确定。
- 评价结果分为事实层、提示层和自然语言层，三者不能混在一起。

## 7. 前端与 UI/UX 升级

### 7.1 设计方向

整体采用“专业训练控制台”而不是普通表单应用。视觉重点是场景、分数、动作状态和控制反馈，不使用营销式大标题、装饰性卡片堆叠或单一色系。

推荐语义色：

- 主色：冰川蓝，用于主操作和焦点。
- 成功：青绿色，用于就绪、完成和正确动作。
- 警告：琥珀色，用于低置信度、轻微偏差和网络延迟。
- 危险：珊瑚红，用于停止、删除、安全保持和严重错误。
- 中性色：蓝灰阶梯，用于背景、边框、文字和次要状态。

浅色和深色都必须使用同一套语义变量，Canvas、图表、弹窗和 3D HUD 也要接入。

### 7.2 布局系统

- 左侧导航：舞蹈包库、机器人指挥中心、训练历史、设置。
- 顶部上下文栏：当前舞蹈包、会话状态、音乐时钟、速度、全屏和全局操作。
- 主内容区域：3D 场景、卡片网格或分析图表。
- 右侧检查器：属性、质量、详情、命令队列或设置分组。
- 底部状态栏：摄像头状态、模型状态、FPS、显存估算、网络和后台任务。
- 全屏模式隐藏非必要导航，但保留紧急停止和退出提示。

### 7.3 组件规范

- 页面标题 `20-24px`，卡片标题 `14-16px`，正文 `13-14px`，辅助信息 `11-12px`。
- 间距统一使用 4、8、12、16、24 的阶梯。
- 卡片、按钮、输入框和抽屉统一 6-8px 圆角。
- 主要按钮、次按钮、幽灵按钮、危险按钮、图标按钮必须有统一状态。
- 图标使用 Lucide 或项目现有图标库，不手绘重复 SVG。
- 图标按钮必须有 Tooltip。
- 进度、质量、网络和摄像头状态使用状态色块，不使用难理解的纯文本。
- 所有表格支持排序、列筛选和空状态。

### 7.4 页面级升级

舞蹈包库：

- 顶部为搜索、筛选、排序和视图切换。
- 卡片靠左排列，统一海报比例。
- 详情使用右侧抽屉，播放音乐和动态预览不打断列表。
- 删除和覆盖资源必须二次确认。

训练页：

- 3D 场景尽量占据主画面。
- 摄像头叠加固定在左上角，允许收起和切换尺寸。
- HUD 使用低干扰半透明面板，不能遮挡机器人主体。
- 关键提示最多保留一层，避免多提示重叠。

历史页：

- 先展示趋势和结论，再展示明细。
- 薄弱部位使用热区或条形图，不只显示数字。
- 复训入口必须能从问题卡片直接进入对应片段。

设置页：

- 左侧分类，右侧内容。
- 顶部搜索设置项。
- 基础项默认展开，高级项默认折叠。
- 底部固定保存栏显示未保存状态、恢复默认和测试连接。

### 7.5 动效与可访问性

- 面板切换使用 `120-180ms` 的淡入或位移。
- 重要状态变化允许短促高亮，但必须支持减少动画。
- 焦点轮廓清晰，键盘可完成主要操作。
- 支持高 DPI、窗口缩放、全屏和最小分辨率。
- 长中文名称不能溢出卡片，使用换行或省略号并显示完整 Tooltip。
- 状态不能只依赖颜色，还要配合文字和图标。

## 8. 6GB 显存性能预算

实时链路目标：

- 摄像头目标 `15 FPS`，允许根据推理耗时降到 `10-12 FPS`。
- MediaPipe 人脸和手势按间隔帧处理，不能每帧同时运行。
- Three.js 默认目标 `45 FPS`，低功耗模式 `30 FPS`。
- 主线程单次布局或绘制不能长时间超过 `50ms`。
- 模型推理、评分和渲染都不能阻塞 UI 线程。
- 显存目标不超过 `4.2GB`，预留系统和其他应用空间。
- 默认只加载一个 3D 角色和一个 3D 场景。

四档降级：

1. 高质量：完整模型、皮肤和场景，60 FPS 渲染。
2. 平衡：45 FPS，降低阴影和粒子，保留手部。
3. 低功耗：30 FPS，骨架或低模，降低人脸和手势频率。
4. 安全模式：关闭 WebEngine 3D，仅保留二维骨架、评分和本地语音。

出现以下情况时自动建议降级：

- GPU 显存占用超过阈值。
- 推理耗时连续超过预算。
- 渲染帧率连续低于目标。
- 摄像头分辨率高于当前设备可承受范围。
- 云端 TTS 或 ASR 延迟持续过高。

## 9. 数据、隐私与可观测性

- SQLite 增加 schema 版本和迁移脚本。
- 动作包增加格式版本、迁移状态和损坏修复入口。
- 训练记录增加动作包 ID、章节、节拍、薄弱片段和设置快照。
- 日志增加会话 ID、命令 trace ID、Worker 名称和云端请求 ID。

## 11. 总体验收标准

1. 新用户能在一次流程中完成视频转舞蹈包、选择角色、开始训练、查看结算和历史对比。
2. 训练页不会出现第二个 3D 人物，也不会把用户转换成 3D。
3. 机器人手掌、手指和人体骨架在主场景中可切换、可观察、可同步。
4. 音乐始终来自舞蹈视频原声，暂停和变速与动作时钟一致。
5. 云端失败、摄像头失败和 3D 加载失败都有明确降级路径。
6. 任一页面都具备空状态、加载状态、错误状态和恢复入口。
7. 6GB 显存下能够连续运行，并能自动进入低功耗或安全模式。
8. 不引入无许可角色、音乐、视频或模型资源。
9. 关闭应用后，Worker、摄像头、音频、WebEngine 和临时文件全部释放。
10. 所有新增行为都有自动化测试或可重复的手动验收脚本。

## 12. 优先建议

如果只能选择一个起点，先做阶段 A。当前项目的主要瓶颈不是某个按钮缺失，而是主窗口承担了过多状态和生命周期职责。先把会话状态机、WorkerRegistry 和设置校验拆出来，后面的舞蹈包详情、历史分析、AI 教练和视觉升级才能低风险落地。
