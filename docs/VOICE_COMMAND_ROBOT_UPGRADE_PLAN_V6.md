## 0. 一句话定义 V6

新增一个“机器人指挥中心”页面：

**用户对着麦克风说“向前走三步”“跳这个舞蹈包的副歌”“慢速跳到 30 秒”“跑起来”“停下”“转个圈”“跳到舞台中间”，系统实时显示识别文字，把自然语言转成结构化机器人命令，再由行为运行时驱动机器人、舞蹈、跑步、跳跃、转身、表情、镜头和场景。**

它不是聊天机器人，也不是让 LLM 直接控制骨骼。它是：

**语音识别 + 语义解析 + 安全校验 + 任务规划 + 动画运行时 + 实时字幕。**

## 1. 模块定位

### 1.1 与现有模块的关系

- 舞蹈包大厅：管理舞蹈资产。
- 镜面训练：用户跟标准舞者跳舞。
- 训练结算：本地评分和 LLM 评价。
- 机器人指挥中心：用户用语言指挥机器人表演、移动、跑跳和播放舞蹈包。
- 角色系统：为机器人和真人角色提供模型、骨骼和重定向。
- 多模态系统：提供手势、人脸、Pose 和音频特征。

### 1.2 新增用户价值

- 比赛演示更有互动性。
- 无需键盘操作即可控制机器人。
- 可以把多个舞蹈包组合成表演指令。
- 可以实时展示自然语言理解、动作规划和 3D 控制。
- 可以用于教学、展示、互动游戏和语音人机交互实验。

### 1.3 不做什么

- 不让 LLM 直接输出骨骼旋转或电机脉冲。
- 不让 LLM 直接执行文件、系统或网络操作。
- 不把每一句话都发送到云端。
- 不依赖单一 ASR 服务。
- 不允许“跳”“跑”“停”等安全命令等待云端响应。
- 不在低端设备上同时运行大型语音模型和多个高模角色。

## 3. 语音命令完整链路

```text
麦克风
  -> 音频采集
  -> 重采样 / 降噪 / 音量归一化
  -> VAD 语音活动检测
  -> 本地安全关键词快速通道
  -> 流式 ASR
  -> 临时字幕
  -> 最终字幕
  -> 文本清洗
  -> 本地规则解析
  -> 复杂指令交给 LLM 结构化解析
  -> 安全校验
  -> 任务规划
  -> 动作队列
  -> 行为运行时
  -> 机器人动画 / 移动 / 摄像 / 语音回复
  -> 字幕和执行状态回写
```

### 3.1 三个通道

#### 通道 A：安全快速通道

处理：

- 停止。
- 暂停。
- 取消。
- 回来。
- 回原位。
- 紧急停止。
- 闭嘴。
- 重新开始。

要求：

- 本地检测。
- 不依赖云端。
- 目标延迟小于 150 毫秒。
- 最高优先级。
- 可以打断当前动作和队列。

#### 通道 B：确定性命令通道

处理：

- 前进、后退、左转、右转。
- 跑、走、跳、蹲、站立。
- 播放舞蹈包。
- 暂停舞蹈包。
- 加速和减速。
- 循环。
- 切换场景和摄像。

要求：

- 字符和关键词规则优先。
- 可离线。
- 低延迟。
- 执行参数有安全边界。

#### 通道 C：LLM 复杂指令通道

处理：

- 复合命令。
- 多步骤命令。
- 模糊描述。
- 组合舞蹈和移动。
- 自然语言条件和目标。
- 歧义澄清。

要求：

- LLM 只输出结构化动作计划。
- 计划必须经过本地验证。
- 不能直接控制骨骼和文件系统。
- 云端失败时回退到规则解析或请求澄清。

## 4. 语音识别人脸

注意：这里的“人脸”属于 V5 的视觉模块，语音控制模块不依赖人脸识别。

语音控制需要的是：

- 麦克风音频。
- 说话者语音活动。
- 识别文本。
- 文本时间戳。
- 文本置信度。
- 是否检测到机器人自身播报的回声。

人脸和手势只用于：

- 用户是否在镜头前。
- 用户是否看向舞台。
- 手势确认复杂命令。
- 表情状态反馈。

语音命令不通过人脸身份决定权限。

## 5. 实时语音识别架构

### 5.1 默认方案

建议支持四种模式：

1. 云端流式 ASR：低延迟、识别质量高、需要网络。
2. 云端短句 ASR：VAD 切句后发送，成本和隐私更可控。
3. 本地 `faster-whisper`：离线、MIT，适合中低配 CPU 或 GPU。
4. 本地 `Vosk`：更轻量，适合低端设备和关键词命令。

### 5.2 推荐默认

比赛默认：

- 本地 VAD。
- 本地紧急关键词检测。
- 网络可用时使用云端流式 ASR。
- 网络不可用时切换到本地 `faster-whisper` 或 Vosk。

低端设备默认：

- 本地 VAD。
- Vosk 或短句模式。
- 只启用常用命令。
- 不持续上传音频。

### 5.3 音频预处理

- 16 kHz 或 16 kHz 兼容采样。
- 单声道。
- 音量归一化。
- 噪声抑制可选。
- 低通滤波。
- 去除机器人 TTS 回声。
- 静音裁剪。
- 音频分片。
- 时间戳对齐。

### 5.4 VAD

- 检测语音起点和终点。
- 避免把键盘声、风扇声和音乐当命令。
- 静音超过阈值后结束当前语句。
- 倒计时和音乐播放时可调整 VAD 灵敏度。
- 机器人说话时暂停普通识别，保留紧急关键词通道。

### 5.5 回声处理

- 机器人播报时降低麦克风输入或多路抑制。
- 建议使用系统级回声消除或 WebAudio 回声消除。
- 不能把机器人自己的声音识别成用户命令。
- 播报期间只允许本地“停止”和“关闭语音”等关键词。
- 对重复识别的机器人语音进行哈希过滤。

### 5.6 临时字幕与最终字幕

临时字幕：

- 快速显示，允许修改。
- 用于告诉用户系统正在听。
- 不执行动作。

最终字幕：

- ASR 完成一句后确定。
- 进入命令解析。
- 记录时间戳和置信度。
- 与临时字幕视觉区分。

### 5.7 语言和口音

- 默认中文。
- 支持中英混合。
- 舞蹈包名称、英文动作名和数字有专门词表。
- 支持用户自定义词典。
- 支持“街舞”“K-pop”“副歌”“慢速”等垂直词。
- 低置信度时不执行危险动作，只请求重复。

## 6. 命令分类与语义结构

### 6.1 意图分类

```text
EMERGENCY_STOP
PAUSE
RESUME
CANCEL
RESET
LOCOMOTION
DANCE
POSE
EMOTE
MOVE_TO
FOLLOW
SCENE
CAMERA
AUDIO
SPEAK
DANCE_PACKAGE
TEACH
SYSTEM
UNKNOWN
```

### 6.2 槽位

- `direction`：前、后、左、右、中间、舞台。
- `distance`：一步、半步、一米、三米。
- `duration`：2 秒、5 拍、30 秒。
- `speed`：0.5 至 2.0 倍。
- `loop_count`：循环次数。
- `dance_package`：舞蹈包名称或 ID。
- `section`：开头、副歌、高潮、结尾、第几段。
- `action`：跳、跑、走、蹲、转圈、挥手、鞠躬。
- `target`：舞台中心、左侧、右侧、前方、原位。
- `camera`：正面、侧面、俯视、跟随、特写。
- `scene`：舞蹈房、比赛舞台、科技演播室。
- `emotion`：开心、认真、庆祝、鼓励。
- `speech_text`：需要机器人说的话。

### 6.3 单动作示例

- “向前走三步。”
- “后退一点。”
- “左转九十度。”
- “跑到舞台中间。”
- “原地跳一下。”
- “蹲下。”
- “站起来。”
- “挥挥手。”
- “鞠个躬。”
- “转个圈。”
- “停下来。”

### 6.4 舞蹈包示例

- “跳这个舞蹈包。”
- “播放舞蹈包。”
- “只跳副歌。”
- “从 30 秒开始。”
- “跳到 45 秒。”
- “用 0.75 倍速跳。”
- “加快到 1.25 倍。”
- “慢一点。”
- “循环三遍。”
- “循环副歌。”
- “跳到舞台中间再跳副歌。”

### 6.5 复合命令示例

- “先跑到舞台中间，然后用 0.75 倍速跳这个舞蹈包的副歌，循环三遍。”
- “先向我挥手，再后退两步，最后鞠躬。”
- “暂停音乐，转到正面镜头，然后重新开始。”
- “跳完副歌后停下，不要继续。”
- “跳到第 2 段，慢慢加速到原速，再循环一次。”

### 6.6 歧义处理

如果一个命令存在多个解释：

- 不猜测执行。
- 显示可选项。
- 通过语音追问。
- 用户可以用“第一个”“第二个”或“取消”回答。
- 高风险动作必须二次确认。

示例：

```text
用户：跳副歌
系统：检测到两个舞蹈包都有副歌，你要跳哪一个？
     第一，K-pop 入门。
     第二，街舞组合。
```

## 7. 命令解析策略

### 7.1 本地确定性解析

优先级最高，使用：

- 精确关键词。
- 正则或规则语法。
- 同义词表。
- 数字和中文数字转换。
- 舞蹈包名称模糊匹配。
- 时间位置解析。
- 速度解析。
- 循环次数解析。

适合：

- 停止。
- 暂停。
- 跑跳。
- 前后左右。
- 播放舞蹈包。
- 速度和循环。
- 常见场景控制。

### 7.2 本地小模型解析

用于：

- 常见同义句。
- 简短复合句。
- 低置信度文本。
- 没有网络时的复杂命令。

模型要求：

- 体积小。
- 可量化。
- CPU 可运行。
- 只输出 JSON。
- 不直接输出骨骼动作。

### 7.3 云端 LLM 解析

只在需要时使用：

- 复合命令。
- 多步骤依赖。
- 条件命令。
- 语言表达不标准。
- 需要澄清或重排任务。

LLM 输出结构：

```json
{
  "schema_version": "1.0",
  "intent": "ROBOT_COMMAND_PLAN",
  "original_text": "",
  "language": "zh-CN",
  "clarification_required": false,
  "steps": [
    {
      "step_id": 1,
      "kind": "move_to",
      "target": "stage_center",
      "duration_s": 2.0,
      "speed": 1.0,
      "depends_on": []
    },
    {
      "step_id": 2,
      "kind": "play_dance",
      "dance_package_id": "",
      "section": "chorus",
      "speed": 0.75,
      "loop_count": 3,
      "depends_on": [1]
    }
  ],
  "reply_text": "",
  "confidence": 0.0,
  "safety_notes": []
}
```

### 7.4 安全校验

本地校验 LLM 计划：

- 意图是否在白名单。
- 动作是否允许。
- 目标是否存在。
- 舞蹈包是否存在。
- 速度是否在范围。
- 循环次数是否超限。
- 距离是否超过舞台边界。
- 任务依赖顺序是否合理。
- 是否包含文件、网络、系统命令。
- 是否包含危险语句。
- 是否需要二次确认。

任何不通过的计划都不得执行。

## 8. 机器人行为规划

### 8.1 规划层和执行层分离

规划层输出：

- 意图。
- 动作步骤。
- 参数。
- 依赖关系。
- 优先级。
- 可取消性。
- 预期完成条件。

执行层负责：

- 加载动作。
- 混合动画。
- 控制根节点。
- 控制摄像机。
- 控制音乐。
- 控制语音。
- 报告完成和失败。

### 8.2 任务图

复杂命令转换为有向任务图：

```text
移动到舞台中心
  -> 播放舞蹈包副歌
     -> 设置 0.75 倍速
     -> 循环 3 次
  -> 回到待机
```

每个任务：

- 有唯一 ID。
- 有执行状态。
- 有依赖。
- 有超时。
- 有取消策略。
- 有失败回退。

### 8.3 动作队列

- 普通命令进入队列末尾。
- 安全命令插入队首或立即执行。
- 新舞蹈命令可以替换旧舞蹈命令，但需要确认。
- 移动和跳跃等冲突动作不能重叠。
- 表情和上身动作可以叠加。
- 同一时刻只能有一个根运动动作。

### 8.4 优先级

```text
紧急停止
  > 暂停 / 取消
  > 安全回原位
  > 立即语音指令
  > 舞蹈播放
  > 移动
  > 表情
  > 镜头
  > 装饰效果
```

## 9. 机器人执行系统

### 9.1 动作类型

- 待机。
- 行走。
- 跑步。
- 跳跃。
- 蹲下。
- 起立。
- 转身。
- 挥手。
- 鞠躬。
- 点头。
- 摇头。
- OK。
- 比心。
- 指向。
- 舞蹈包动作。
- 场景切换。
- 镜头移动。

### 9.2 动画层

建议使用分层动画：

- 基础层：站立、行走、跑步、跳跃。
- 舞蹈层：舞蹈包动作。
- 上身层：挥手、鞠躬、OK、表情。
- 面部层：表情和嘴型。
- 道具层：披风、手指、配件。
- 镜头层：跟随和特写。

冲突规则：

- 跑步时不能同时播放原地舞蹈。
- 跳跃不能和蹲下同时执行。
- 舞蹈包播放时，普通移动命令先暂停舞蹈或进入混合。
- 上身手势可以叠加在走路之上。
- 表情可以叠加在任何动作之上。

### 9.3 根运动

- 跑、走、跳、转身都有根运动。
- 舞蹈包可以保留原地或位移。
- 舞台边界限制位移。
- 到达目标点后落脚稳定。
- 机器人没有真实物理，但仍限制速度、加速度和边界。

### 9.4 过渡

- Idle 到 Walk 使用交叉淡化。
- Walk 到 Run 根据速度平滑过渡。
- 舞蹈到 Idle 使用收尾动作。
- 跳跃必须有起跳、空中、落地三个阶段。
- 紧急停止需要迅速稳定姿态，不产生大幅度下坠。
- 任务失败回到安全姿势。

## 11. 实时字幕系统

### 11.1 字幕类型

- 用户临时识别文本。
- 用户最终识别文本。
- 系统澄清问题。
- 系统执行回复。
- 机器人台词。
- 错误和警告。

### 11.2 字幕行结构

每行记录：

- 时间。
- 来源：用户、系统、机器人。
- 原始文本。
- 清洗后文本。
- 识别置信度。
- 意图。
- 参数。
- 执行状态。
- 错误原因。

### 11.3 字幕显示

```text
[21:36:12] 你：先跑到中间，然后跳副歌，慢速循环三遍
[21:36:12] 解析：移动 → 播放舞蹈包 → 副歌 → 0.75 倍速 → 3 次循环
[21:36:12] 机器人：好的，我先移动到舞台中间。
[21:36:14] 状态：播放舞蹈包副歌，循环 1/3（0.75 倍速）
```

### 11.4 字幕与隐私

- 默认只保存在当前会话。
- 用户可以选择保存到训练记录。
- 不默认上传完整历史。
- 敏感词和 API Key 不写入日志。
- 可以导出为本地文本。
- 一键清空。

## 12. 语言反馈与 TTS

### 12.1 机器人回复

- 执行前简短确认。
- 执行中只报关键节点。
- 执行完成后短总结。
- 失败时说明原因和替代方案。
- 不持续播报每一步，避免噪声。

### 12.2 示例

- “好的，正在移动到舞台中间。”
- “现在用 0.75 倍速播放副歌。”
- “已经完成三轮循环。”
- “没有找到这个舞蹈包，请重新选择。”
- “这个动作会超出舞台边界，我没有执行。”
- “好的，停止。”

### 12.3 防回声

- TTS 播放时标记音频时间段。
- ASR 忽略机器人自己播报的音频。
- 支持“打断”功能。
- 紧急关键词优先。
- 播报期间降低音乐音量，但保留节拍。

## 14. 延迟目标

| 环节 | 目标 |
|---|---:|
| 音频采集缓冲 | 20 至 50 ms |
| VAD 检测 | 50 至 150 ms |
| 本地安全关键词 | 小于 150 ms |
| 流式 ASR 临时结果 | 150 至 500 ms |
| ASR 最终结果 | 300 至 900 ms |
| 本地命令解析 | 小于 100 ms |
| LLM 复杂计划 | 0.5 至 2 秒 |
| 动作开始 | 0.2 至 0.6 秒 |
| 停止命令 | 小于 150 ms |
| TTS 开始 | 0.3 至 1 秒 |

体验原则：

- 停止必须快。
- 复杂命令可以稍慢，但要有“正在思考”反馈。
- 不要让界面看起来卡死。
- 临时字幕先显示，最终动作后执行。
- 解析失败要给出可理解的错误。

## 15. 云端和本地模式

### 15.1 云优先模式

- 云端流式 ASR。
- 云端 LLM 解析复杂命令。
- 云端 TTS 可选。
- 本地安全关键词仍然生效。
- 适合网络稳定的比赛或演示。

### 15.2 混合模式

- 本地 VAD。
- 云端 ASR。
- 本地规则解析常见命令。
- 只有复杂命令才调用云端 LLM。
- 识别失败时切换本地模型。

### 15.3 本地模式

- 本地 VAD。
- `faster-whisper` 或 `Vosk`。
- 本地规则和本地小型模型。
- 本地 TTS。
- 没有网络也可以演示基础控制。

### 15.4 静默模式

- 只显示文字。
- 不播放机器人语音。
- 适合宿舍和比赛现场。
- 仍然执行语言控制。

## 16. 隐私与安全

### 16.1 音频

- 默认不保存原始音频。
- 只保留识别文本，且用户可以选择是否保存。
- 云端 ASR 需要明确告知。
- 不在后台持续上传静音和噪声。
- VAD 避免无意义上传。

### 16.2 语音日志

- 默认保存最近一段时间。
- 可一键清空。
- 不保存机器人 TTS 原文以外的私密内容。
- API Key 不写入字幕。
- 导出字幕时提示包含个人信息。

### 16.3 LLM 安全

- 语音文本视为不可信数据。
- LLM 只输出固定 JSON。
- 不允许文件操作、系统命令、网络请求和代码执行。
- 动作只能在白名单中。
- 所有参数本地校验。
- 危险动作需要二次确认。
- 不允许“忽略之前规则”等提示词注入改变安全约束。

### 16.4 动作安全

- 虚拟机器人也要限制舞台边界。
- 跑跳和转圈设置最大速度。
- 连续动作设置冷却。
- 紧急停止优先于所有命令。
- 机器人摔倒、碰撞、越界时回到安全状态。
- 真实机器人接口只在未来版本启用，且必须独立安全层。

## 17. 低端设备方案

### 17.1 默认低端配置

- 1 个机器人。
- 720p 或 480p 场景。
- 24 至 30 FPS 渲染。
- 无阴影或简化接触阴影。
- 无 HDRI。
- 舞蹈动作使用低模角色或骨架。
- Vosk 或短句 ASR。
- 规则解析优先。
- 复杂命令才使用云端。
- 字幕只保留最近 50 条。

### 17.2 动作简化

- 关闭布娃娃物理。
- 关闭复杂披风。
- 关闭粒子和流体。
- 关闭镜头景深。
- 关闭环境反射。
- 降低脚步尘土和特效。
- 低端设备只保留一套动作过渡。

### 17.3 ASR 降级

1. 云端流式 ASR 不可用，切本地短句 ASR。
2. 本地大模型不可用，切 Vosk 关键词。
3. 语音识别太慢，切按住说话。
4. 完全不可用，切键盘输入命令，保留相同意图解析逻辑。

## 21. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| ASR 识别错误 | 执行错误动作 | 展示临时字幕，危险动作二次确认 |
| 网络延迟 | 指令反应慢 | 本地规则和本地 VAD |
| LLM 幻觉 | 生成非法动作 | JSON 白名单和本地验证 |
| 提示词注入 | 绕过安全规则 | 输入视为数据，禁止执行输入指令 |
| 机器人 TTS 回声 | 自己触发命令 | 回声消除，播报期间过滤 |
| 复合命令顺序错误 | 任务冲突 | 任务图和依赖校验 |
| 跑跳导致越界 | 视觉异常 | 舞台边界和速度限制 |
| 低端设备卡顿 | 语音延迟 | Vosk、短句模式、低模 |
| 音乐和语音重叠 | 识别受影响 | 音量 ducking 和回声保护 |
| 隐私担忧 | 用户不愿使用 | 本地 VAD、可选云端、无原始音频保存 |
| 动作包不存在 | 无法执行 | 模糊匹配、澄清、候选选择 |
| 紧急停止失效 | 体验和安全问题 | 独立本地关键词通道和最高优先级 |

## 22. 最终推荐

机器人指挥中心应该成为 V6 的独立模块，而不是塞进训练页。

推荐默认组合：

```text
本地麦克风采集
  -> 本地 VAD
  -> 云端流式 ASR
  -> 本地规则解析
  -> 复杂命令调用 LLM
  -> 本地安全校验
  -> 任务图
  -> 动作队列
  -> 机器人行为运行时
  -> 实时字幕
  -> TTS 回复
```

最终体验是：

**用户说话，字幕实时出现；常见命令立刻执行；复杂命令被拆成动作计划；机器人能跑、跳、舞蹈、转身、挥手、切换镜头和场景；任何时刻说“停止”都能立即中断。**

这是一个独立的语音机器人控制模块，也是项目中最有交互创新性的玩法之一。
