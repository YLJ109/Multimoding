## 0. 一句话定义 V7

在机器人指挥中心中新增“实时模仿模式”：

**摄像头实时识别人物动作，机器人或所选角色同步模仿用户的全身、手部、头部和表情；用户还可以通过语音随时暂停、切换模仿范围、调整平滑度、改变镜头，并实时切换机器人皮肤。**

新增体验包括：

- “开始模仿我。”
- “停止模仿。”
- “只模仿上半身。”
- “增强手部动作。”
- “减少抖动。”
- “镜像我。”
- “不要镜像。”
- “切换赛博皮肤。”
- “上一个皮肤。”
- “锁定这个皮肤。”
- “跟我舞。”
- “机器人自由表演。”

V7 的核心不是增加一个按钮，而是建立可复用的实时姿态总线和可热切换的角色皮肤系统。

## 1. 与现有模块的关系

### 1.1 复用现有能力

当前项目已有：

- `CameraSource` 摄像头读取。
- `YoloPoseEstimator` 2D 姿态。
- `normalize_frame` 坐标标准化。
- `BaselinePoseLifter` 保守深度。
- `retarget_frame` 3D 角色桥接。
- `SceneWidget` Three.js 渲染。
- `LiveTrainingWorker` 实时评分。
- MediaPipe Hands 和 Face 规划。
- 语音机器人指挥中心规划。
- 多角色和重定向规划。

V7 不复制这些代码，而是抽出共享姿态服务：

```text
摄像头
  -> CameraSource
  -> YoloPoseEstimator
  -> 标准化
  -> PoseFrameBus
     -> 评分订阅者
     -> 模仿重定向订阅者
     -> 动作质量订阅者
     -> 录制/回放订阅者
```

### 1.2 两种运行模式

#### 语音命令模式

机器人由语言命令驱动：

- 走、跑、跳、挥手、转身。
- 播放舞蹈包。
- 切换场景和镜头。
- 执行任务队列。

#### 实时模仿模式

机器人由摄像头前的人驱动：

- 全身动作。
- 上半身。
- 手部和手势。
- 头部方向。
- 表情。
- 可选根节点移动。

#### 混合模式

语音和摄像头同时工作：

- 语音控制模式切换。
- 语音控制模仿范围。
- 语音控制平滑、镜像、速度和灵敏度。
- 语音控制皮肤。
- 语音控制镜头和场景。
- 安全命令始终优先。

混合模式是默认推荐模式。

## 3. 实时模仿完整链路

```text
摄像头帧
  -> 帧时间戳
  -> 主人物检测和跟踪
  -> YOLO Pose
  -> 关节点置信度
  -> 缺口修复
  -> 坐标标准化
  -> 短时滤波
  -> 根节点和身体朝向
  -> 手部特征
  -> 头部和面部特征
  -> 姿态融合
  -> 目标机器人重定向
  -> 关节约束
  -> 表情和材质映射
  -> Three.js 机器人
  -> 状态质量面板
```

### 3.1 频率设计

| 模块 | 目标频率 | 低端频率 |
|---|---:|---:|
| 摄像头采集 | 30 FPS | 15 至 20 FPS |
| YOLO Pose | 12 至 18 FPS | 8 至 12 FPS |
| MediaPipe Hands | 5 至 10 FPS | 3 至 5 FPS |
| MediaPipe Face | 3 至 8 FPS | 关闭或 2 至 4 FPS |
| 重定向 | 每个新姿态帧 | 每个新姿态帧 |
| 3D 渲染 | 30 至 60 FPS | 24 至 30 FPS |
| 姿态插值 | 每渲染帧 | 每渲染帧 |

关键策略：

- 姿态推理不必和渲染频率相同。
- 渲染通过插值平滑显示。
- 重定向只在有新姿态时计算。
- 手部和人脸低频运行。
- 不把原始高分辨率帧复制到多个模块。

## 4. Pose 总线设计

### 4.1 为什么需要总线

如果评分、模仿、录制、手势和数据显示各自调用一次 YOLO，会导致：

- 重复推理。
- GPU 显存翻倍。
- 帧时间戳不一致。
- UI 和角色动作不同步。
- Worker 生命周期混乱。

统一只做一次姿态推理，多个订阅者共享纯数据。

### 4.2 核心数据结构

`PoseFramePacket` 建议包含：

- 帧 ID。
- 摄像头时间戳。
- 单调时钟时间。
- 主人物框。
- COCO-17 关键点。
- 每关节置信度。
- 图像宽度和高度。
- 是否需要镜像。
- 跟踪 ID。
- 检测质量。
- 是否包含其他人物。
- 手部摘要。
- 人脸摘要。

### 4.3 订阅者

- `ScoringSubscriber`：实时评分。
- `ImitationSubscriber`：机器人模仿。
- `RecordingSubscriber`：可选录像。
- `QualitySubscriber`：质量面板。
- `PreviewSubscriber`：骨架叠加。
- `ActionRecognitionSubscriber`：未来动作识别。

### 4.4 背压策略

- 如果渲染跟不上，丢弃旧姿态帧，只保留最新帧。
- 如果评分跟不上，评分使用重采样后的帧。
- 如果手部模型跟不上，只处理最近的手部区域。
- 不允许队列无限增长。
- 每个订阅者有独立背压策略。

## 5. 人体标准化

### 5.1 坐标标准

- x 向右。
- y 向上。
- z 为深度。
- 原点在髋部中点。
- 距离以躯干长度为初始单位。
- 输出到机器人前转换为米制。
- 根节点和身体局部姿态分离。

### 5.2 左右方向

- 默认使用用户本人视角。
- 面部朝向摄像头时，画面右侧通常是用户左手。
- 镜像模式只改变显示和根节点方向，不改变评分语义。
- 机器人目标角色需要自己的左右映射。
- 用户转身时重新确认身体朝向。

### 5.3 主人物

- 单人模式：选择画面中最大、最稳定、最靠中心的人物。
- 多人模式：用户手动锁定；锁定信息只保存在本地。
- 如果主人物离开画面，显示恢复提示。
- 不把第二名人物动作混入机器人。

### 5.4 缺口修复

- 单帧缺失：插值。
- 短时缺失：预测最多 200 至 300 毫秒。
- 长时缺失：冻结最后姿态并显示“不可判断”。
- 重新出现：短时交叉淡化。
- 不允许无限预测。

## 6. 动作重定向

### 6.1 源到机器人

源：

- 用户人体骨架。
- 17 个身体关节。
- 可选手部 21 点和脸部特征。

目标：

- 机器人 Humanoid 骨架。
- 目标关节名称和初始姿态。
- 目标骨骼长度和比例。

核心步骤：

1. 计算源骨骼相对旋转。
2. 将旋转转换到目标坐标系。
3. 应用目标初始姿态。
4. 对关节进行约束。
5. 处理根节点。
6. 平滑四元数。
7. 映射手部和面部。
8. 输出机器人姿态。

### 6.2 直接旋转和 IK

直接旋转适合：

- 肩、肘、腕。
- 髋、膝、踝。
- 躯干和头部。

IK 适合：

- 脚落地。
- 手摸目标点。
- 需要保持脚部稳定。
- 需要避免脚底滑动。

首版建议：

- 先做相对旋转。
- 在脚部接触阶段增加轻量两步 IK。
- 不在低端模式运行复杂 IK。

### 6.3 约束

- 肘部不能反折。
- 膝盖不能反折。
- 肩部限制极限旋转。
- 脊柱限制异常弯折。
- 头颈限制极端角度。
- 手腕限制翻转。
- 机器人有硬质关节时增加更严格角度限制。

### 6.4 平滑

- 静止时高平滑。
- 快速动作时降低平滑。
- 单关节噪声单独过滤。
- 根节点使用低通滤波。
- 置信度低时冻结而不是继续放大噪声。
- 用户调节“平滑强度”时非线性改变参数。

## 7. 手部和人脸映射

### 7.1 手部

如果机器人支持手掌：

- 映射手掌方向。
- 映射手腕旋转。
- 映射手指开合。

如果机器人没有手指：

- 将手势映射为整体手部姿势。
- OK 手势映射为拇指和食指靠近的姿态。
- 张手映射为五指展开的机械手。
- 握拳映射为闭合机械手。
- 比心映射为简单图案或表情。

### 7.2 人脸

如果机器人有屏幕或面部材质：

- 张嘴映射屏幕嘴型。
- 微笑映射亮色或表情。
- 眨眼映射屏幕灯光。
- 转头映射头部骨骼。
- 不允许重建真实人脸。

如果机器人没有面部：

- 只映射头部朝向。
- 用头顶灯、胸灯或眼睛灯反映状态。
- 表情分析可关闭。

### 7.3 隐私

- 原始人脸帧不上传。
- 面部关键点不持久化。
- 只保存聚合统计。
- 用户开关关闭后立即停止人脸处理。
- 宿舍模式自动模糊背景和其他人物。

## 9. 摄像头实时校准

### 9.1 校准项

- 全身是否可见。
- 双脚是否在画面内。
- 双手是否在安全区域。
- 人物是否过近。
- 人物是否过远。
- 光照是否足够。
- 画面是否过曝或过暗。
- 是否只有主人物。
- 左右方向是否正确。
- 是否需要镜像。
- 摄像头延迟。
- 用户身高和机器人身高比例。

### 9.2 校准流程

1. 用户站在安全区域。
2. 系统检测全身。
3. 提示站直。
4. 做 T-Pose 或 A-Pose。
5. 系统记录初始姿态。
6. 验证左右手。
7. 验证膝盖和脚。
8. 测试挥手和蹲下。
9. 保存校准配置。

### 9.3 校准结果

- 站立比例。
- 肩宽比例。
- 躯干长度。
- 腿长比例。
- 手臂长度。
- 初始朝向。
- 镜像状态。
- 根节点偏移。
- 摄像头延迟补偿。

校准只保存数值，不保存原始人脸或视频。

## 10. 动作质量与降级

### 10.1 质量指标

- 全身覆盖率。
- 关键关节置信度。
- 手部可见率。
- 人脸可见率。
- 最大连续缺失帧。
- 姿态抖动。
- 动作延迟。
- 实时帧率。
- 摄像头丢帧。

### 10.2 质量等级

- 优秀：机器人稳定模仿。
- 良好：普通动作稳定。
- 可用：部分关节缺少，机器人使用回退。
- 不稳定：只显示骨架或冻结。
- 不可用：停止模仿并提示调整站位。

### 10.3 降级顺序

1. 降低手部频率。
2. 降低人脸频率。
3. 关闭面部表情。
4. 关闭手指映射。
5. 降低 YOLO 频率。
6. 关闭根节点移动。
7. 切换骨架角色。
8. 冻结为安全姿态。
9. 切回语音命令模式。

## 11. 机器人皮肤系统

### 11.1 皮肤定义

机器人皮肤至少由六层组成：

1. 基础模型。
2. 骨架和绑定。
3. 材质参数。
4. 贴图资源。
5. 配件和替换部件。
6. 特效和表情映射。

皮肤不是复制一个完整模型，而是对基础角色应用可视化变体。

### 11.2 皮肤类型

- 颜色皮肤。
- PBR 材质皮肤。
- 赛车涂装。
- 工业机甲。
- 赛博霓虹。
- 太空探索。
- 救援消防。
- 医疗辅助。
- 比赛限定。
- 全息幽灵。
- 低模节能皮肤。
- 用户自定义皮肤。

### 11.3 皮肤组成

一个皮肤可以包含：

- 主色和辅助色。
- 金属度。
- 粗糙度。
- 自发光颜色和强度。
- 屏幕纹理。
- 灯带动画。
- 盔甲替换件。
- 头盔或面罩。
- 手指和手掌颜色。
- 披风或附件。
- 表情映射。

### 11.4 皮肤包结构

建议扩展名：`*.dskin`。

```text
cyber_neon.dskin
  manifest.json
  preview.jpg
  materials.json
  textures/
  accessories/
  effects.json
  license.json
  checksums.json
```

`manifest.json` 包含：

- 皮肤 ID。
- 名称。
- 基础模型 ID。
- 兼容骨架版本。
- 材质数。
- 贴图最大尺寸。
- 是否透明。
- 是否支持自发光。
- 是否支持手指。
- 是否支持面部映射。
- 性能等级。
- 来源和许可证。
- 是否允许导出。

### 11.5 皮肤切换逻辑

```text
选择皮肤
  -> 检查模型兼容
  -> 检查许可证
  -> 异步加载材质和贴图
  -> 预编译材质
  -> 替换材质槽
  -> 替换配件
  -> 保留骨骼和当前姿态
  -> 淡出旧皮肤
  -> 淡入新皮肤
  -> 释放无引用资源
```

必须保证：

- 换肤不重置机器人姿态。
- 换肤不打断模仿。
- 换肤不重新加载骨架。
- 换肤失败自动回到旧皮肤。
- 正在播放舞蹈包时换肤无停顿。
- 低端设备可以只换主色和自发光。

### 11.6 皮肤命令

- “换赛博皮肤。”
- “切换到工业皮肤。”
- “上一个皮肤。”
- “下一个皮肤。”
- “随机皮肤。”
- “回到默认皮肤。”
- “把灯调成蓝色。”
- “增强发光。”
- “降低金属感。”
- “只换颜色，不换配件。”
- “保存当前皮肤组合。”

### 11.7 动态皮肤

可选：

- 节拍时灯带闪烁。
- 连击增加发光。
- 错误时闪红灯。
- 成功时金色脉冲。
- 机器人说话时屏幕嘴型变化。
- 模仿时显示手部状态。
- 低电量或低性能时切换简单材质。

动态皮肤必须受性能档位限制，不能让粒子系统拖慢模仿。

## 13. 专业代码架构

建议目录：

```text
src/dance_mirror/
  imitation/
    controller.py          模仿模式总控制器
    state.py               模仿状态机
    scope.py               模仿范围
    calibration.py         人体校准
    quality.py             姿态质量
    smoothing.py           自适应平滑
    root_motion.py         根节点移动
    hand_mapping.py        手部映射
    face_mapping.py        头部和表情映射

  pose_stream/
    packet.py              姿态纯数据
    bus.py                 姿态总线
    subscribers.py         评分、模仿、预览订阅者
    backpressure.py        队列和丢帧策略

  skins/
    manifest.py            皮肤元数据
    registry.py            皮肤索引
    loader.py              皮肤加载
    material_compiler.py   材质预编译
    runtime.py             热切换运行时
    cache.py               材质和贴图缓存
    licenses.py            皮肤许可证
    variants.py            颜色、配件和特效

  renderer/
    actors/
      actor_controller.py
      actor_state.py
      skin_binding.py
```
### 13.1 核心模块职责

- `imitation`：决定模仿什么、如何平滑、如何降级。
- `pose_stream`：只负责帧传递和背压，不做评分。
- `skins`：只负责皮肤资源和热切换。
- `renderer.actors`：只负责把姿态和皮肤应用到角色。
- `robot_runtime`：处理语音动作和任务队列。
- `voice`：只负责识别和指令。

### 13.2 线程边界

- 摄像头采集线程：采集和缓冲。
- Pose Worker：YOLO、手部和人脸。
- 融合 Worker：标准化、质量和融合。
- 姿态总线：纯数据分发。
- 主线程：UI、字幕和状态。
- WebEngine：角色、骨骼、材质和动画。
- 皮肤加载 Worker：文件检查、哈希和贴图准备。

任何 Worker 不能直接操作 QWidget、QPixmap 或 WebEngine 对象。

### 13.3 关键数据流

```text
VoiceWorker -> ImitationController
PoseWorker -> PoseFrameBus
PoseFrameBus -> ImitationController
ImitationController -> Retarget
Retarget -> ActorController
SkinManager -> ActorController
ActorController -> SceneRuntime
ImitationController -> QualityPanel
```

## 14. 延迟与性能预算

### 14.1 目标

| 环境 | 端到端延迟目标 |
|---|---:|
| 3060 6GB 平衡 | 100 至 160 ms |
| 低端平衡 | 150 至 250 ms |
| 高性能桌面 | 70 至 120 ms |

端到端包括：

- 摄像头采集。
- 姿态推理。
- 标准化。
- 重定向。
- 渲染。
- 显示。

### 14.2 优化措施

- 720p 摄像头优先。
- YOLO FP16。
- 单帧只推理主人物。
- 手部和人脸低频。
- 姿态帧插值。
- 渲染与推理分离。
- 只发送必要数据到 WebEngine。
- 皮肤材质预编译。
- 纹理缓存和 LOD。
- 关闭不需要的阴影和反射。
- 低端设备关闭人脸和手指。

### 14.3 低端设备方案

- 640×480 或 720p。
- Pose 8 至 12 FPS。
- 3D 24 至 30 FPS。
- 无 Hand 或只做 OK 手势。
- 无人脸表情。
- 单色皮肤。
- 骨架角色回退。
- 动作平滑自动增强。

## 15. 隐私与安全

### 15.1 视频

- 摄像头画面本地处理。

- 不允许通过皮肤包加载系统命令。

## 19. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 姿态推理过慢 | 模仿延迟明显 | 降低分辨率、频率，插值渲染 |
| 重复推理 | GPU 过载 | Pose 总线共享结果 |
| 左右方向错误 | 机器人镜像错位 | 校准和镜像配置 |
| 低置信度抖动 | 机器人乱跳 | 置信度门限、冻结和滤波 |
| 手部模型过慢 | 延迟增加 | 低频运行和 ROI 裁剪 |
| 人脸隐私敏感 | 用户拒绝 | 本地处理、默认关闭表情 |
| 换肤卡顿 | 体验差 | 预编译材质、异步加载、缓存 |
| 皮肤资源泄漏 | 显存越来越高 | 引用计数和 LRU 释放 |
| 语音和模仿冲突 | 动作跳变 | 优先级和模式状态机 |
| 舞台越界 | 视觉异常 | 根节点限制和边界 |
| 低端设备不足 | 卡顿 | 骨架回退和简单皮肤 |
| 摄像头丢失 | 模仿中断 | 冻结、提示、切语音模式 |

## 20. 最终推荐组合

默认高配：

```text
YOLO Pose
  + MediaPipe Hands
  + MediaPipe Face
  + Pose 总线
  + 全身重定向
  + 手部和头部映射
  + 皮肤热切换
  + 语音混合控制
```

平衡配置：

```text
YOLO Pose
  + Hands 低频
  + Face 关闭或低频
  + 全身重定向
  + 基础皮肤
  + 语音控制
```

低端配置：

```text
YOLO Pose
  + 无 Face
  + 仅 OK 手势
  + 骨架或低模机器人
  + 单色皮肤
  + 本地规则语音
```

最终体验：

**人可以实时控制机器人，机器人可以实时模仿人；用户可以语音切换模仿范围、调整动作质量、切换镜头和场景，还可以实时替换皮肤而不打断动作。语音控制、模仿、舞蹈包、多角色和 LLM 评价共享同一套姿态和角色运行时，不再各自为战。**

这才是真正专业、可扩展、适合比赛展示的实时人机共舞系统。
