## 0. 最终产品定义

DanceMirror V9 最终只有两种核心大画面体验：

### 0.1 学习舞蹈模式

**一段真人舞蹈视频先离线转换成 3D 动作包，再由 3D 机器人作为标准舞者在主舞台跳舞。**

- 大画面：3D 机器人标准舞蹈场景。
- 左上角：摄像头小窗。
- 摄像头中：用户本人、二维骨架、关节点、判定颜色和全身安全框。
- 大画面中：视频转换后的机器人、三维骨架、脚底落点、动作轨迹和评分热区。
- 用户不做 3D 人物重建。
- 用户不显示 3D 头像、3D 人体、SMPL 模型或网格重建。
- 用户动作只在摄像头画面中以 2D 骨架表现。
- 评分在标准动作特征和用户二维姿态特征之间完成。
- 标准动作必须是 3D 机器人，不是把用户转成 3D。

一句话：

**视频中的人变成 3D 机器人；摄像头前的人保持 2D 骨架；大画面只展示 3D 机器人标准舞。**

### 0.2 机器人指挥中心模式

**摄像头前的人驱动主舞台中的 3D 机器人实时模仿、跳舞、移动和执行语音命令。**

- 大画面：3D 机器人舞台。
- 左上角：摄像头小窗。
- 摄像头中：用户本人、二维骨架和手势叠加。
- 大画面中：机器人实时模仿用户动作，并始终绘制机器人骨架。
- 用户仍然不做 3D 人物重建。
- 用户姿态经过重定向后只作用于机器人。
- 机器人可以有角色、皮肤、场景、舞蹈包、表情和语音反馈。
- 机器人指挥中心不再是左右两个人物舞台，只有一个主机器人舞台加摄像头小窗。

一句话：

**摄像头前的人保持 2D；输出到主舞台的是 3D 机器人；机器人骨架始终显示。**

### 0.3 两个模式共同遵守的规则

| 规则 | 学习舞蹈 | 机器人指挥中心 |
|---|---|---|
| 主画面 | 3D 机器人场景 | 3D 机器人场景 |
| 左上角 | 摄像头小窗 | 摄像头小窗 |
| 标准动作 | 视频转 3D 机器人 | 机器人动作或舞蹈包 |
| 用户 3D 人物 | 不做 | 不做 |
| 用户 2D 骨架 | 必须显示 | 必须显示 |
| 机器人 3D 骨架 | 必须显示 | 必须显示 |
| 用户 3D 网格 | 不做 | 不做 |
| 机器人模型 | 必须支持 | 必须支持 |
| 全身安全框 | 显示 | 显示 |
| 实时评分 | 显示 | 可显示动作质量 |
| 语音控制 | 支持提示和暂停 | 支持完整指挥 |
| 皮肤切换 | 可支持标准机器人皮肤 | 完整热切换 |
| 音乐 | 主时钟 | 按舞蹈包使用 |
| 低端回退 | 机器人骨架模式 | 机器人骨架或安全保持 |

## 1. 对旧方案的最后修正

### 1.1 不再采用用户 3D 舞台

V2 和 V3 曾提出：

- 左舞台显示标准动作。
- 右舞台显示用户动作。
- 左右舞台都使用 3D 角色。
- 摄像头实时驱动用户角色。

V9 最终改为：

- 学习舞蹈页只有一个大 3D 机器人舞台。
- 用户不在大舞台中出现。
- 用户只在左上角摄像头小窗中以 2D 骨架出现。
- 标准视频先转成 3D 动作包，再由机器人重定向播放。
- 评分比较发生在特征层，不要求用户变成 3D。

这样做的直接收益：

- 减少一个实时 3D 角色。
- 不再需要用户 3D 重建和 SMPL。
- 不再需要用户骨骼网格和 3D 衣物。
- 降低 6GB 显存压力。
- 消除左右模型距离过近的问题。
- 避免两个人员角色同时占满大画面。
- 让用户更专注看标准机器人动作。
- 用户自己的动作通过摄像头骨骼反馈已经足够清晰。

### 1.2 不再把“骨架”理解为辅助物

V9 规定骨架不是可选装饰，而是核心反馈层。

必须始终存在：

1. 大画面机器人三维骨架。
2. 左上角摄像头用户二维骨架。
3. 评分后的分部位颜色。
4. 关键关节置信度。
5. 当前动作或目标动作提示。

允许调整：

- 骨架透明度。
- 骨架线宽。
- 关节点大小。
- 颜色主题。
- 是否显示轨迹。
- 是否显示关节点编号。

不允许完全关闭骨架，只允许切换为简化骨架、标准骨架或详细骨架。

### 1.3 机器人是主视觉，不是小模型

大画面机器人必须：

- 位于舞台中轴或合理构图位置。
- 全身可见。
- 头顶到脚底留有画面边距。
- 脚底与地面接触。
- 不因动作幅度切掉手和脚。
- 支持自动取景。
- 支持全身、半身和自由镜头，但默认全身。
- 骨架与模型使用同一套最终骨骼位置。
- 模型切换后骨架仍然匹配。

### 1.4 摄像头小窗是辅助视角，不抢主画面

左上角摄像头小窗必须：

- 保持固定位置。
- 保持固定宽高比。
- 不遮挡机器人的头部和主要动作区。
- 默认小尺寸。
- 支持三档尺寸或折叠。
- 用户能清楚看到自己的全身骨架。
- 骨架叠加不改变原始摄像头像素。
- 不把摄像头画面作为主背景铺满。
- 不与 Three.js 共享 GPU 纹理。

## 3. 学习舞蹈模式的完整行为

### 3.1 舞蹈包准备

1. 用户选择舞蹈包。
2. 系统读取 `manifest.json`。
3. 系统读取 3D 动作序列。
4. 系统读取比较特征。
5. 系统读取音乐、节拍和分段。
6. 系统读取默认机器人、场景和皮肤。
7. 检查资源完整性。
8. 检查显存和渲染档位。
9. 显示舞蹈包预览。
10. 等待用户进入准备阶段。

### 3.2 准备阶段

准备阶段显示：

- 摄像头小窗。
- 用户全身安全框。
- 双脚位置。
- 与摄像头距离。
- 光照质量。
- 单人检测。
- 骨架置信度。
- 3D 机器人待机。
- 音乐准备状态。
- OK 手势或按钮开始。
- 3、2、1 倒计时。

用户不需要出现在大画面中。

### 3.3 训练阶段

训练开始后：

- 音乐作为主时钟。
- 3D 机器人从动作包播放标准动作。
- 机器人骨架同步显示。
- 摄像头小窗显示用户 2D 骨架。
- 用户姿态进入特征评分。
- 摄像头骨架按关节误差着色。
- 大画面机器人骨架按动作阶段着色。
- 右侧 HUD 显示分数、连击和提示。
- 错误持续一段时间后才语音提醒。
- 低置信度不扣分，也不增加连击。
- 暂停时机器人和音乐同时暂停。
- 速度变化同时作用于音乐、机器人、评分和节拍。

### 3.4 结算阶段

结算显示：

- 总分。
- 准确度。
- 节奏。
- 稳定度。
- 覆盖率。
- 左右手。
- 左右腿。
- 躯干。
- 脚步。
- 薄弱时间段。
- 可回练片段。
- 语音总结。
- 云端结构化总结。

用户 3D 人物仍然不生成。

## 4. 机器人指挥中心的完整行为

### 4.1 待机

- 大画面显示机器人待机动画。
- 机器人骨架显示。
- 摄像头小窗未连接时显示提示。
- 语音服务未启动时显示本地按钮。
- 用户可选择角色、皮肤和场景。

### 4.2 实时模仿

1. 用户说“开始模仿我”或点击按钮。
2. 摄像头启动。
3. 摄像头小窗显示用户 2D 骨架。
4. YOLO 提取 COCO-17。
5. 用户不做 3D 重建。
6. 姿态经过标准化和短时滤波。
7. 姿态重定向到机器人骨骼。
8. 机器人实时模仿。
9. 机器人 3D 骨架始终显示。
10. 摄像头小窗显示用户 2D 骨架。
11. 用户可通过语音调整范围、平滑和镜像。
12. 用户可通过语音切换皮肤。
13. 摄像头丢失时进入安全保持。

### 4.3 语音指挥

- 语音控制机器人动作。
- 语音控制舞蹈包。
- 语音控制场景和镜头。
- 语音控制皮肤。
- 语音控制模仿范围。
- 语音控制暂停、恢复和停止。
- 所有安全命令走本地快速通道。
- LLM 只输出白名单意图。
- LLM 不直接输出骨骼。

### 4.4 模仿和语音混合

- 语音负责改变控制参数。
- 摄像头负责驱动机器人身体。
- 皮肤只改变材质。
- 场景只改变环境。
- 舞蹈包与实时模仿不能同时控制同一骨骼。
- 紧急停止优先级最高。
- 机器人骨架不因换肤或换场景消失。

## 5. 人物表示策略

### 5.1 明确的数据表示

| 对象 | 数据表示 | 是否进入 3D 主场景 | 是否显示骨架 |
|---|---|---:|---:|
| 视频中的标准舞者 | 视频帧 -> 2D 姿态 -> 3D 动作包 | 间接进入机器人 | 机器人骨架 |
| 标准动作机器人 | GLB/VRM + Humanoid | 是 | 是 |
| 摄像头前用户 | 二维关键点 | 否 | 摄像头中显示 |
| 用户评分特征 | 二维标准化特征 | 否 | 颜色叠加 |
| 机器人输出姿态 | Humanoid 四元数 | 是 | 是 |
| 机器人皮肤 | 材质和配件 | 是 | 不影响 |
| 机器人口型 | 屏幕或材质状态 | 是 | 不影响 |

### 5.2 用户为什么不做 3D

- 单目摄像头 3D 重建误差大。
- 6GB 显存不适合同时运行 YOLO、Hands、Face 和大 3D 重建网络。
- 用户 3D 人物不是本产品的主要视觉目标。
- 标准动作机器人已经承担大画面视觉。
- 2D 骨架足以支持位置、角度、节奏和稳定性评分。
- 用户更容易理解摄像头上的骨架反馈。
- 减少深度遮挡、漂浮和骨骼比例错误。

### 5.3 用户评分不依赖用户 3D 网格

评分特征来自：

- 二维关节点位置。
- 标准化骨骼比例。
- 关节角度。
- 左右对称。
- 运动方向。
- 运动速度。
- 动作幅度。
- 关节稳定性。
- 与参考动作的时间对齐。
- 关节覆盖率和置信度。
- 节奏跟随。
- 连续稳定时间。

可选内部数值：

- 保守深度。
- 身体朝向。
- 左右手深度差。

即使使用这些数值，也不生成用户 3D 人物，不渲染用户 3D 骨架，不保存用户网格。

### 5.4 视频转机器人

视频中的舞者处理链路：

```text
原始视频
  -> 帧读取
  -> YOLO Pose
  -> COCO-17 二维骨架
  -> 缺口修复
  -> 2D/3D 动作提升
  -> 坐标标准化
  -> Humanoid 重定向
  -> 机器人动作片段
  -> 质量检查
  -> .dmotion 动作包
```

在正式训练中：

```text
.dmotion
  -> 标准机器人动作
  -> 机器人 3D 场景
  -> 机器人骨架
```

视频中的人不会直接出现在大画面，用户也不会在大画面中被 3D 重建。

## 6. 骨架系统

### 6.1 骨架类型

| 骨架 | 所在位置 | 坐标 | 数据来源 |
|---|---|---|---|
| 用户二维骨架 | 左上角摄像头 | 图像像素或归一化 2D | YOLO COCO-17 |
| 用户关节点 | 左上角摄像头 | 图像坐标 | YOLO confidence |
| 机器人三维骨架 | 大画面 | 世界米制坐标 | 机器人最终骨骼 |
| 机器人关节点 | 大画面 | 世界米制坐标 | 机器人骨骼节点 |
| 参考轨迹 | 大画面 | 世界坐标 | 动作包 |
| 误差热区 | 摄像头或 HUD | 分部位 | 评分模块 |

### 6.2 机器人骨架必须来自最终骨骼

机器人骨架不能继续使用源视频的 2D 点。

正确顺序：

1. 动作包加载。
2. Humanoid 重定向。
3. 动画骨骼更新。
4. 读取机器人世界变换。
5. 生成骨架世界坐标。
6. 骨架与模型一起渲染。
7. 评分热区映射到对应骨骼。

这样可以保证：

- 模型和骨架不会错位。
- 不同角色骨架都能正确显示。
- 重定向变化能立即反映。
- 骨架展示的是机器人真实动作。
- 换肤不会影响骨架。

### 6.3 摄像头二维骨架

绘制内容：

- 17 个 COCO 关节。
- 标准骨架连线。
- 左右手颜色区分。
- 左右腿颜色区分。
- 躯干中轴。
- 头部节点。
- 置信度低于阈值的关节变暗。
- 预测关节使用虚线。
- 超出安全区域时提示。
- 分部位评分颜色。
- 当前错误关节高亮。

### 6.4 骨架颜色

默认建议：

| 状态 | 颜色 |
|---|---|
| 正常关节 | 青白色 |
| 用户左半身 | 蓝色系 |
| 用户右半身 | 橙色系 |
| 当前动作正确 | 绿色 |
| 轻微偏差 | 黄色 |
| 明显偏差 | 橙红色 |
| 低置信度 | 灰色 |
| 预测或插值 | 虚线灰色 |
| 机器人参考骨架 | 青色或白色 |
| 机器人实时模仿 | 金色或绿色 |

颜色不能是唯一信息源，必须同时显示文字或形状差异。

### 6.5 骨架显示等级

- 简化：主要骨骼和关节。
- 标准：17 点、20 条线和关节分数。
- 详细：21 点手部、面部框、轨迹和编号。

骨架不能完全关闭，只能切换等级。

## 7. 摄像头小窗实现

### 7.1 性能路线

摄像头画面不进入 Three.js 纹理系统。

推荐：

```text
Camera Worker
  -> 原始帧
  -> 缩放
  -> 姿态叠加数据
  -> QImage
  -> 主线程
  -> QPixmap
  -> QLabel/自绘控件
```

原因：

- 减少 GPU 纹理上传。
- 避免 WebEngine GPU 上下文竞争。
- 方便 QPainter 绘制骨骼。
- 1080p 原图不需要反复复制。
- 可以在主线程之外完成缩放和叠加准备。

### 7.2 叠加层

叠加层计算：

- 关键点缩放。
- 骨架连线。
- 关节点圆形。
- 框和标签。
- 置信度颜色。
- 安全区域。
- 手势点。
- 人脸框。
- 隐私模糊区域。

不要在原始帧上反复修改像素后再重新编码。

### 7.3 小窗位置

- 主工作区左上角。
- 距离顶部 16 px。
- 距离左侧 16 px。
- 悬浮在 3D 场景之上。
- 更高层级显示。
- 不参与 Three.js 深度遮挡。
- 拖动后仍可吸附左上角。
- 支持收起、小、中、大三档。
- 默认不遮挡机器人头部。

### 7.4 小窗状态

- 未连接。
- 请求权限。
- 正在初始化。
- 摄像头在线。
- 全身未就位。
- 多人检测。
- 光照不足。
- 隐私遮罩。
- 摄像头断线。
- 正在恢复。

## 11. 跟舞评分逻辑

### 11.1 评分输入

- 参考动作比较特征。
- 用户二维标准化特征。
- 音乐时间。
- 节拍。
- 关节置信度。
- 动作覆盖。
- 历史短时窗口。

### 11.2 不参与评分

- 用户外貌。
- 用户身份。
- 用户性别。
- 用户年龄。
- 用户情绪诊断。
- 人脸身份向量。
- 原始视频画面。
- 用户 3D 网格。

### 11.3 评分步骤

1. 获取参考动作特征。
2. 获取用户二维姿态。
3. 检查用户覆盖率和置信度。
4. 将用户坐标标准化。
5. 按音乐时间对齐参考帧。
6. 计算关节位置特征。
7. 计算关节角度特征。
8. 计算左右对称。
9. 计算速度与节奏。
10. 计算稳定性。
11. 过滤低置信度。
12. 产生分部位分数。
13. 产生总分数。
14. 产生骨架颜色。
15. 产生提示候选。
16. 交给冷却策略和 TTS。

### 11.4 低置信度规则

- 低置信度关节不扣分。
- 覆盖不足时总评分降权。
- 用户离开画面时暂停评分。
- 恢复后重新对齐。
- 不允许用预测骨架伪造高分。
- 错误超过持续时间才播报。
- 同一提示有冷却时间。

### 11.5 参考动作映射

动作包应保存：

- 3D 机器人动作。
- 评分比较特征。
- 参考二维投影或标准相机参数。
- 身体朝向信息。
- 动作分段。
- 节拍和时间戳。
- 质量标记。

训练中不要求重建视频里的真人，也不要求重建摄像头前的人。

## 13. 页面切换和资源生命周期

  -> 保存会话

  -> 停止订阅

9. 释放骨架和材质。
10. 退出 Worker。
11. 保存记录。

## 16. 视觉规范和细致体验

### 16.1 主画面

- 机器人是唯一主角色。
- 场景不遮挡骨架。
- 地板有落点参考。
- 灯光突出身体轮廓。
- 动作阶段有轻微 HUD 变化。
- 不在每帧添加粒子。
- 不在高难度动作时切换镜头。
- 不制造眩晕。

### 16.2 摄像头小窗

- 固定左上角。
- 不遮挡机器人头部。
- 有清晰边框。
- 有在线和离线状态。
- 有隐私遮罩标记。
- 有骨架置信度。
- 有低延迟指示。
- 可折叠但默认可见。

### 16.3 骨架

- 线条足够细但不虚。
- 关节点不遮住动作。
- 低置信度变灰。
- 预测关节使用虚线。
- 分部位错误颜色一致。
- 骨架颜色与 HUD 图例一致。
- 不只使用颜色传达错误。

- 分数变化有缓冲区。
- 不因单帧抖动大幅跳分。
- 错误提示持续后才播报。
- 同一提示有冷却。
- 分部位分数与骨架颜色一致。
- 回练片段可点击定位。

### 16.5 语音

- 临时字幕和最终字幕分开。
- 命令确认显示在底部。
- TTS 不掩盖音乐。
- 音乐播放时降低提示频率。
- 暂停和停止优先于其他语音。

## 17. 失败处理

| 失败 | 学习舞蹈 | 机器人指挥中心 |
|---|---|---|
| 摄像头失败 | 暂停评分，保留机器人回放 | 安全保持，等待恢复 |
| YOLO 失败 | 暂停评分，显示明确原因 | 停止模仿，机器人待机 |
| 机器人模型失败 | 只显示机器人骨架 | 只显示骨架或安全姿态 |
| 动作包损坏 | 不从该包开始 | 不播放该动作 |
| 音乐失败 | 允许无音乐练习 | 不影响动作命令 |
| WebEngine 失败 | 原生骨架回退 | 原生骨架回退 |
| 皮肤失败 | 保留默认皮肤 | 保留旧皮肤 |
| 云端失败 | 本地评分继续 | 本地命令继续 |
| 麦克风失败 | 可点击控制 | 可点击控制 |
| 显存不足 | 降级模型和场景 | 降级皮肤和模型 |
| 骨架数据异常 | 冻结异常关节 | 冻结异常关节 |

## 18. 隐私和安全

### 18.1 摄像头

- 本地处理。
- 默认不上传。
- 默认不保存。
- 室友自动模糊。
- 可设置裁剪区域。
- 关闭后立即停止。

### 18.2 用户骨架

- 只保存聚合统计。
- 用户主动开启后才保存序列。
- 不上传关键点历史。
- 不建立身份模板。
- 不生成 3D 人物。

### 18.3 视频参考

- 视频只在导入阶段解析。
- 训练阶段读取动作包，不读取原视频。
- 不默认上传原视频。
- 不把原视频打进动作包。

### 18.4 机器人模型和皮肤

- 记录许可证。
- 用户导入模型本地使用。
- 不随项目分发 IP 模型。
- 皮肤包不执行脚本。
- 不加载远程纹理 URL。

## 22. 最终结论

V9 的最终视觉和系统关系可以用一句话概括：

**大画面永远是 3D 机器人，左上角永远是摄像头骨骼；视频中的人通过动作包变成机器人，摄像头前的人保持 2D 骨架；学习舞蹈展示标准机器人，机器人指挥中心展示实时模仿机器人。**

系统设计必须保证：

```text
视频中的舞者
  -> 3D 动作包
  -> 3D 机器人
  -> 大画面
  -> 3D 骨架

摄像头前用户
  -> 2D 骨架
  -> 左上角小窗
  -> 二维特征评分
  -> 不生成 3D 人物

机器人指挥中心用户
  -> 2D 骨架
  -> 左上角小窗
  -> 重定向
  -> 3D 机器人实时模仿
  -> 机器人 3D 骨架
```

这就是 V9 的终极产品形态：

- 视觉统一。
- 结构简单。
- 显存可控。
- 用户不需要 3D 重建。
- 视频动作仍然能转成 3D 机器人。
- 骨架始终可见。
- 跟舞训练和语音指挥共用机器人运行时。
- 后续可以继续添加角色、皮肤、场景、手势和 LLM，而不破坏核心交互。
