## 0. 一句话定义 V3

V3 不再只是“选择视频后进入训练”，而是完整舞蹈游戏流程：

**打开舞蹈包大厅 → 选择卡片 → 查看海报与音乐 → 全身就位 → 做 OK 手势 → 3、2、1 倒计时 → 跟着 3D 舞蹈包跳舞 → 实时评分和语音提示 → 结算评级 → 重练薄弱片段。**

所有舞蹈包必须先成为完整资产，至少包含：

- 3D 动作数据。
- 一张可展示的海报。
- 一首可播放的音乐，或者经过授权绑定的本地音乐引用。
- 节拍、速度、分段和动作难度。
- 动作质量报告和来源说明。
- 可选的模型、场景和重定向资料。

没有音乐或没有动作数据的包只能处于“草稿”状态，不能开始正式游戏。

## 1. 当前项目为什么显得简单

当前实现是“功能链路可运行”，还不是“成熟产品”：

| 当前状态 | 用户感受 | V3 解决方式 |
|---|---|---|
| 首页直接选择视频和摄像头 | 像开发工具，不像游戏 | 新增舞蹈包大厅和完整卡片流程 |
| 动作包只是 JSON 文件 | 看不到、记不住、不能管理 | 卡片、海报、标签、搜索和详情页 |
| 导入后立即回放 | 缺少准备和仪式感 | 导入向导、质量检查、音乐绑定和预览 |
| 右视口可能空白 | 两个舞台不完整 | 回放角色、待机动作和独立舞台 |
| 没有统一开场 | 不知道什么时候开始 | 全身就位、OK 手势、3、2、1 倒计时 |
| 评分只显示总分 | 游戏反馈弱 | 节拍判定、连击、分部位得分和等级 |
| 速度不能控制 | 不便于教学 | 0.5 至 2.0 倍速和练习模式 |
| 音乐没有纳入主流程 | 无法按拍点游戏 | 音乐作为主时钟和节拍来源 |
| 删除、重命名只能操作文件 | 容易误删、体验差 | 卡片操作、回收站和撤销 |
| 低端设备适配不足 | 容易卡顿或 OOM | 独立性能档位和自动降级 |

## 2. V3 页面地图

建议主导航调整为：

```text
首页
舞蹈包大厅
训练游戏
训练记录
资产中心
设置
```

### 2.1 首页

首页只承担三件事：

- 继续上次舞蹈包。
- 快速进入舞蹈包大厅。
- 添加舞蹈包或查看设备状态。

首页不应该堆满模型路径、摄像头编号和底层参数。

### 2.2 舞蹈包大厅

这是 V3 的核心新页面。

包含：

- 舞蹈包卡片网格。
- 搜索、筛选、排序。
- 添加舞蹈包。
- 查看详情。
- 开始、试跳、重命名、删除、导出和收藏。
- 导入任务的实时进度。
- 最近练习和个人最佳成绩。

### 2.3 导入向导

把一段真人视频转换成一个正式舞蹈包。

步骤：

1. 选择视频。
2. 选择人物和动作范围。
3. 解析 2D 和 3D 动作。
4. 查看动作质量。
5. 选择海报。
6. 绑定音乐。
7. 分析节拍和同步。
8. 设置名称、标签、难度和练习分段。
9. 预览并保存为 `*.dmotion`。

### 2.4 舞蹈包详情页

显示：

- 大尺寸海报。
- 3D 动作预览。
- 音乐播放器和 BPM。
- 动作时长、帧数、难度、舞种和作者。
- 质量评分和遮挡段提示。
- 个人最佳、练习次数和最近成绩。
- 开始游戏、试跳、选择机器人、选择场景、编辑、导出和删除。

### 2.5 训练游戏页

- 顶部：歌曲、进度、分数、连击、速度和暂停。
- 中部：左侧 3D 标准舞者，右侧用户或回放角色。
- 底部：当前判定、分部位评分、节拍条、动作提示和练习控制。
- 准备阶段额外显示全身框、站位箭头和 OK 手势确认。
- 结算后进入结果页。

### 2.6 结算页

- 总分、等级、星级、个人最佳和进步值。
- 动作准确、节奏、稳定、覆盖、完成度。
- 左右手、左右腿、躯干、脚步的专项分。
- 失误时间轴和动作热区。
- 按片段重练。
- 机器人语音总结和云端文字总结。
- 保存报告、导出摘要和返回大厅。

## 3. 舞蹈包大厅详细设计

## 3.1 卡片布局

每张卡片建议采用 3:4 或 16:10 的海报比。考虑桌面端信息密度，推荐 16:10：

```text
┌──────────────────────────────┐
│                              │
│          舞蹈海报             │
│                              │
│  [收藏]          [难度标签]   │
├──────────────────────────────┤
│ 舞蹈名称                      │
│ 00:48 · 128 BPM · 街舞        │
│ ★★★★☆  最佳 87.5             │
│ 最近练习：今天 21:36           │
└──────────────────────────────┘
```

卡片上必须显示：

- 海报。
- 名称。
- 时长。
- BPM。
- 舞种或风格。
- 难度。
- 最佳分或星级。
- 是否收藏。
- 动作包状态：草稿、可用、优秀、损坏、缺少音乐。
- 模型兼容状态。

### 3.2 卡片动作

单击卡片：

- 打开舞蹈包详情页。

双击卡片：

- 如果包已就绪，直接进入准备阶段。

卡片悬浮时显示操作：

- 开始。
- 试跳。
- 详情。
- 重命名。
- 收藏。
- 更多菜单。

更多菜单包含：

- 选择默认机器人。
- 选择默认场景。
- 编辑标签和难度。
- 更换海报。
- 更换音乐绑定。
- 重新分析节拍。
- 迁移旧动作包。
- 导出舞蹈包。
- 删除。

### 3.3 重命名

- 名称允许中文、英文、数字和常用符号。
- 卡片重命名不直接改文件，先修改动作包索引和 manifest，用户确认后再写回。
- 如果文件正在播放，禁止重命名并给出原因。
- 重名时提供“保留两者”“自动加序号”“取消”。
- 支持批量改名规则，例如统一添加舞种前缀。

### 3.4 删除

不能只弹一个普通确认框。

删除流程：

1. 显示包名、大小、练习次数和个人最佳。
2. 如果存在未导出内容，明确提示。
3. 默认移动到本地回收站，不直接永久删除。
4. 删除后提供 10 秒撤销通知。
5. 永久删除需要二次确认。
6. 正在被训练页使用的包禁止删除。

### 3.5 海报

海报来源优先级：

1. 用户手动选择的视频帧。
2. 系统生成的最佳姿态候选图。
3. 3D 预览自动渲染图。
4. 默认舞种封面。

海报生成建议：

- 从视频中采样每 0.5 至 1 秒一帧。
- 过滤全身不完整、模糊、严重遮挡和低置信度帧。
- 计算清晰度、姿态完整性、动作张力和构图。
- 选出 3 至 5 个候选。
- 用户选择一张，或者自动选最高分。
- 海报上不烧录文字，名称和标签由 UI 叠加，方便后续改名。
- 生成 640×400 左右的主海报和 320×200 缩略图。
- 用户可以选择是否保留舞者面部；宿舍隐私场景可默认使用 3D 角色海报。

### 3.6 搜索、筛选和排序

搜索：

- 名称。
- 标签。
- 舞种。
- 作者。
- 来源视频名称。
- 动作包 ID。
- 备注。

筛选：

- 全部、收藏、最近练习、未练习、草稿、缺少音乐、质量优秀、低难度、高难度。
- 舞种：街舞、爵士、K-pop、民族舞、健身操、其他。
- 时长：30 秒内、30 至 60 秒、1 至 3 分钟、3 分钟以上。
- 速度范围。
- 兼容模型。
- 设备性能等级。

排序：

- 最近使用。
- 创建时间。
- 名称。
- 最佳成绩。
- 难度。
- 时长。
- 下载或导入频率。

### 3.7 空状态

没有舞蹈包时显示：

- 添加视频并转换。
- 导入 `.dmotion` 包。
- 使用内置示例动作包。
- 查看动作包制作说明。

不要只显示“暂无数据”。

## 4. 视频转换为舞蹈包的导入向导

## 4.1 入口

三个入口：

- 舞蹈包大厅的“添加舞蹈包”卡片。
- 首页的“从视频创建”。
- 直接将视频拖入大厅窗口。

拖入后先创建一张“处理中卡片”，让用户立即看到任务已接收。

### 4.2 步骤一：选择视频

显示：

- 文件路径。
- 分辨率、FPS、时长、音轨是否存在。
- 版权声明确认。
- 是否包含多人。
- 预估解析时间。
- 预估磁盘和显存占用。

用户可以选择：

- 完整视频。
- 指定起止时间。
- 只提取某一段。

### 4.3 步骤二：选择人物与动作范围

- 自动检测主要人物。
- 用户点击画面确认目标舞者。
- 检查全身是否可见。
- 标记严重遮挡片段。
- 选择左右方向。
- 选择镜像规则。
- 选择是否保留原地位置或保留移动轨迹。

如果视频中多人频繁交换位置，应阻止“一键自动”并引导用户逐段确认。

### 4.4 步骤三：动作解析

解析阶段分为：

1. 视频解码和采样。
2. YOLO Pose 2D 提取。
3. 单人跟踪。
4. 短缺口修复。
5. 3D 动作提升。
6. 骨架归一化。
7. 重定向测试。
8. 动作质量评估。

界面显示：

- 当前帧和总帧数。
- 当前步骤。
- GPU 和显存状态。
- 可取消按钮。
- 解析错误只影响当前包，不阻塞应用。

### 4.5 步骤四：动作质量检查

质量报告包含：

- 检测覆盖率。
- 全身可见比例。
- 关节点平均置信度。
- 连续缺失段。
- 左右手遮挡段。
- 脚下缺失段。
- 快速旋转和跳变段。
- 3D 抖动指数。
- 建议状态：优秀、可用、需要修补、不建议发布。

用户可以：

- 查看每个异常段。
- 手动选择“保留但标记”。
- 删除明显无效片段。
- 让系统自动打断动作分段。
- 选择不把某些低质量片段纳入评分。

### 4.6 步骤五：选择海报

展示候选图片和姿态图。

操作：

- 选择视频帧。
- 选择 3D 渲染图。
- 从本地上传图片。
- 调整裁切和中心点。
- 设置隐私遮蔽。
- 预览卡片效果。

### 4.7 步骤六：绑定音乐

这是 V3 的强制步骤。

一个正式舞蹈包必须有音乐来源：

- 视频原声。
- 用户选择的本地音频文件。
- 已授权的内置音乐。
- 无版权练习节拍音轨。

音乐元数据包括：

- 文件路径或包内引用。
- 标题、作者、来源和许可证。
- 时长和采样率。
- 音量。
- 淡入淡出。
- 是否允许随包导出。

如果用户没有音乐，系统可以生成节拍练习音轨，但不能把它伪装成原歌曲。

### 4.8 步骤七：节拍和同步

需要生成：

- BPM。
- 节拍点。
- 重拍点。
- 音乐偏移。
- 动作与音乐的时间偏移。
- 动作分段。
- 高潮段和重复段。
- 关键动作提示点。

界面提供：

- 点击测试节拍。
- 拖动音频偏移。
- 慢速试听。
- 选择首拍。
- 预览 3D 动作与音乐的同步。

音频偏移必须可保存到动作包，否则不同设备的起播会有明显误差。

### 4.9 步骤八：设置动作包信息

字段：

- 名称。
- 副标题。
- 舞种。
- 难度 1 至 5 星。
- 标签。
- 作者或来源说明。
- 版权说明。
- 默认机器人。
- 默认场景。
- 默认速度。
- 练习分段。
- 是否公开导出。

### 4.10 步骤九：预览并保存

预览：

- 左舞台 3D 标准动作。
- 右舞台选中机器人。
- 音乐播放。
- 海报卡片预览。
- 动作分段和时间轴。

保存后：

- 写入 `*.dmotion`。
- 更新 SQLite 索引。
- 生成缩略图。
- 关闭导入向导。
- 卡片以动画加入大厅。

### 4.11 导入任务卡片

导入中可以显示：

```text
正在处理：
  [进度条]
  解析动作 35%
  检测到 438/1236 帧
  可以取消
```

完成后：

- 成功：显示“查看舞蹈包”和“立即试跳”。
- 失败：显示错误原因、日志入口和建议。
- 缺少音乐：显示“补充音乐”按钮。
- 质量不足：显示“查看低质量片段”。

## 5. `.dmotion` V2 包结构

在 V2 方案基础上扩展为游戏化舞蹈包。

```text
example.dmotion
  manifest.json
  gameplay.json
  poses.npz
  quality.npz
  retarget.json
  cover.jpg
  cover_small.jpg
  beatmap.json
  audio/
    music.ogg
  audio_license.json
  checksums.json
  source_info.json
```

### 5.1 `manifest.json`

至少包含：

- 格式版本。
- 动作包 ID。
- 名称和副标题。
- 作者和来源。
- 创建时间和修改时间。
- 时长、FPS、帧数。
- 动作套路类型。
- 难度。
- 标签。
- 默认速度。
- 默认模型和场景。
- 坐标系和单位。
- 音乐引用方式。
- 数据质量等级。
- 支持的设备档位。
- 是否包含原视频、音乐和可分发资产。

### 5.2 `gameplay.json`

包含：

- BPM。
- 每拍时长。
- 重拍位置。
- 分段列表。
- 评分窗口。
- 主要评分关节。
- 动作提示文本。
- 语音触发点。
- 练习模式建议。
- 难度修正参数。
- 失败保护和暂停规则。

### 5.3 `beatmap.json`

包含：

- 每个节拍的时间。
- 是否重拍。
- 对应动作帧。
- 对应动作分段。
- 是否需要语音提示。
- 节奏强度。

### 5.4 海报

必须包含：

- `cover.jpg`：主海报。
- `cover_small.jpg`：卡片缩略图。

海报可以来自视频帧、3D 渲染或用户上传，但许可证信息必须和动作包分离记录。

### 5.5 音乐

两种模式：

- 包内音乐：只有许可证允许再分发时才能包含。
- 本地音乐引用：动作包只保存用户本地路径和文件哈希，不把歌曲打包给其他人。

舞蹈包可以在没有音乐文件时保存为草稿，但不能开始正式游戏。

### 5.6 旧包迁移

- 旧 `*.dmotion.json` 可读取。
- 迁移时自动生成海报候选。
- 没有音乐时引导用户绑定音乐。
- 没有节拍时运行一次节拍分析。
- 迁移不覆盖原文件。
- 迁移失败时保留原包并给出原因。

## 6. 音乐、节拍与速度系统

## 6.1 音乐为什么必须成为主时钟

跳舞游戏中，音乐不能跟随 3D 动画，应该让 3D 动画、评分和提示服从音乐时间轴。

原因：

- 音乐停顿和恢复必须稳定。
- 用户听感优先于渲染帧率。
- 渲染帧率波动时，动作和音乐不能越来越偏。
- 倒计时必须落在音乐拍点上。
- 评分的时间窗口才有意义。

设计原则：

- 音频播放器负责主时间。
- 3D 渲染只读取插值后的音乐时间。
- 姿态识别保留自己的采样时间，再映射到音乐时间。
- 暂停时 3D、评分和音乐同时冻结。
- 恢复时从同一音乐位置继续。

### 6.2 音乐控制

- 播放。
- 暂停。
- 恢复。
- 重播。
- 拖动进度。
- 选择片段。
- 循环。
- 音量。
- 静音。
- 节拍音轨开关。
- 人声提示音量。
- 音频延迟校准。

### 6.3 速度控制

默认速度：

- 0.5 倍：新手分解。
- 0.65 倍：慢速学习。
- 0.75 倍：基础练习。
- 0.9 倍：接近原速。
- 1.0 倍：标准速度。
- 1.1 倍：进阶。
- 1.25 倍：挑战。
- 1.5 倍：高手。
- 1.75 倍和 2.0 倍：极限模式，仅在用户确认后开放。

速度调整必须同时影响：

- 音乐。
- 3D 参考角色。
- 动作分段。
- 节拍点。
- 评分窗口。
- 倒计时。
- 语音提示。

如果当前音频后端改变速度会改变音高，界面必须明确提示。后续可以增加离线生成 0.75、1.0、1.25 版本的音乐缓存，以减少音高变化。

### 6.4 速度分档与游戏规则

- 慢速模式不计入个人最佳。
- 标准速度计入主排行榜。
- 加速模式可以获得额外分数倍率，但不能掩盖动作错误。
- 速度改变不改变动作包原始数据，只改变播放映射。
- 速度改变后，评分容差按时间比例换算，不能直接沿用原毫秒数。

### 6.5 暂停和语音

- 暂停音乐时停止动作评分。
- 暂停期间不累计连击。
- 长时间暂停后恢复需要重新做 3、2、1 倒计时。
- 云端 TTS 播报时自动降低音乐音量 40% 至 70%。
- 本地 TTS 和云端 TTS 使用同一播报队列，避免重叠。
- 音乐和人声提示必须有优先级，不能让 TTS 覆盖节拍引导。

## 7. 全身就位检查

## 7.1 目标

用户选择舞蹈包后，系统必须先确认用户真正准备好，而不是摄像头一打开就立即开始评分。

检查项：

- 画面中只有主要人物。
- 头部可见。
- 肩部可见。
- 双手可见。
- 髋部可见。
- 双腿可见。
- 双脚可见。
- 人物位于安全区域。
- 与摄像头距离合适。
- 画面亮度可接受。
- 主要关节置信度达标。
- 地面边界没有裁切。
- 左右方向已确认。
- 隐私遮蔽已生效。

### 7.2 视觉引导

使用一个半透明人物轮廓范围：

- 绿色：完全就位。
- 黄色：部分关节不确定。
- 红色：关键部位缺失或人物过多。
- 箭头：提示用户向前、向后、向左、向右。
- 脚底框：提示脚部是否在画面内。
- 头顶和脚底安全线。

不要只显示一句“请站好”。

### 7.3 就位分数

显示 0 至 100 的 Ready 值：

- 人体覆盖率。
- 关键关节置信度。
- 头部和脚部可见性。
- 画面中心度。
- 亮度。
- 多人干扰。
- 估算距离。

进入 OK 手势之前，Ready 值必须稳定达到阈值。

### 7.4 设备自适应

低端设备可以降低：

- 摄像头分辨率。
- 姿态检测频率。
- 就位检查频率。
- 骨架细节。
- 预览渲染帧率。

但全身可见、手部手势和评分关键关节不能降级到不可用。

## 8. OK 手势确认

## 8.1 技术事实

当前 YOLO Pose 的 COCO-17 只包含腕关节，不包含手指关节，因此不能可靠识别真正的 OK 手势。

不能把“手腕位置看起来像圆圈”直接当成 OK。那样会误触发。

### 8.2 推荐实现

新增独立 `HandGestureWorker`：

- 使用本地手部 21 点关键点模型。
- 候选方案：MediaPipe Hand Landmarker，Apache 2.0。
- 仅在准备阶段运行，不参与正式评分主循环。
- 识别完成后立即释放或降频，减少显存和 CPU 占用。
- 支持单手或指定右手。
- 手势结果只传布尔事件和置信度，不上传手指关键点。

### 8.3 OK 判定逻辑

需要同时满足：

- 拇指尖和食指尖距离接近。
- 拇指和食指形成一个近似闭合环。
- 其余三根手指有足够伸展度。
- 手部置信度达标。
- 手掌位于摄像头可见区域。
- 手势持续时间达到 0.8 至 1.2 秒。
- 全身就位检查已经通过。

这样可以减少偶然比划导致的误触发。

### 8.4 手势状态

```text
未检测
检测中
保持中
确认成功
保持过短
超出画面
模型不可用
```

界面显示：

- 手部轮廓或简化反馈。
- 保持进度环。
- “请保持 OK 手势”提示。
- 成功后播放轻提示音。

### 8.5 回退方案

如果手部模型在当前设备不可用，提供两种回退：

- 双臂举过头顶并保持 1 秒。
- 按空格键确认准备完成。

回退方案必须在界面明确标注，不能假装已经识别 OK 手势。

### 8.6 防作弊和防误触

- 只有全身体检通过后才能触发。
- 手势确认后 1 秒内不能再次触发。
- 暂停恢复后需要重新确认。
- 用户离开画面后取消准备状态。
- 检测到第二个人进入关键区域时暂停准备。
- 不保存手部图像和身份信息。

## 9. 游戏状态机

### 9.1 状态列表

```text
空闲
选择舞蹈包
检查环境
等待全身就位
等待 OK 手势
倒计时
音乐前奏
正式跟舞
暂停
恢复倒计时
重新连接
结算
查看结果
返回大厅
```

### 9.2 状态转换

1. 大厅选择舞蹈包。
2. 进入准备页。
3. 检查摄像头、模型、音乐和动作包。
4. 显示全身站位引导。
5. Ready 值达标。
6. 提示做 OK 手势。
7. OK 手势保持成功。
8. 播放音乐前奏。
9. 语音和画面同步倒数 3、2、1。
10. 进入正式跟舞。
11. 用户暂停或系统自动暂停。
12. 恢复时重新进行短倒计时。
13. 音乐结束或用户提前结束。
14. 进入结算。
15. 保存成绩和报告。
16. 返回大厅或重练。

### 9.3 自动暂停条件

- 用户离开画面超过阈值。
- 全身关键部位连续丢失。
- 摄像头断开。
- 显存不足导致姿态处理停止。
- 第二个人大量遮挡。
- 用户手动切换窗口导致摄像头失去焦点，可选暂停。
- 音乐播放异常。

自动暂停时：

- 音乐暂停。
- 评分冻结。
- 不增加连击。
- 显示恢复引导。
- 恢复后至少进行 2 拍或 3 秒倒计时。

### 9.4 倒计时设计

- 默认是 3、2、1、开始，不直接报 0。
- 倒计时与音乐拍点绑定。
- 视觉数字、语音和节拍声三者同步。
- 最后一次“开始”落在一个重拍上。
- 低端设备可以省略动画，但不能省略倒计时。

## 11. 评分系统

## 11.1 总体权重

建议正式评分权重：

| 维度 | 权重 | 说明 |
|---|---:|---|
| 姿态准确 | 45% | 主要关节角度、方向和幅度 |
| 节奏同步 | 20% | 动作峰值和音乐拍点的时间差 |
| 动作稳定 | 10% | 抖动、突变、重心不稳 |
| 有效覆盖 | 10% | 摄像头能判断的动作比例 |
| 完整完成 | 10% | 动作阶段是否完成 |
| 游戏连击 | 5% | 只作为游戏表现加成 |

总分为 100 分。

连击不能抵消真实动作错误。用户跳错但连击不断，总分仍然要受到姿态和节奏惩罚。

## 11.2 分项评分

- 左上肢。
- 右上肢。
- 左下肢。
- 右下肢。
- 躯干和重心。
- 头部和朝向。
- 脚步和地面动作。
- 节奏。
- 流畅度。
- 动作完整度。

## 11.3 判定窗口

建议判定：

| 等级 | 姿态误差 | 节奏误差 | 得分 |
|---|---:|---:|---:|
| Perfect | 接近参考 | 小于 80 ms | 100% |
| Great | 小幅偏差 | 小于 160 ms | 85% |
| Good | 可见偏差 | 小于 280 ms | 70% |
| Miss | 明显错误或错拍 | 大于 400 ms | 0% 至 30% |

最终参数必须用真实测试视频和用户体验调校，不能只按理论值写死。

## 11.4 置信度规则

- 低置信度关节不参与错误判定。
- 低置信度帧不增加连击，也不扣分。
- 连续低置信度超过阈值，自动暂停并提示调整站位。
- 遮挡导致无法判断时，结果页标记为“不确定”，不伪造分数。
- 评分界面显示“当前不可判断”而不是 0 分。

## 11.5 时间对齐

- 实时阶段使用短窗口搜索最佳对齐。
- 训练结束后使用 DTW 对完整动作序列复核。
- 实时分数和最终分数使用同一套上限，不出现结算突然暴涨。
- 暂停和重新连接时间段不参与评分。
- 允许用户设置容错等级，新手模式更宽松。

## 11.6 等级和星级

| 分数 | 等级 | 星级 |
|---:|---|---:|
| 95 至 100 | S | 5 |
| 88 至 94 | A+ | 5 |
| 80 至 87 | A | 4 |
| 70 至 79 | B | 3 |
| 60 至 69 | C | 2 |
| 40 至 59 | D | 1 |
| 0 至 39 | E | 0 |

等级必须同时满足最低有效覆盖率和最少完成动作阶段，不能靠只跳几拍拿高分。

## 13. 低端设备优化方案

## 13.1 目标

低端设备仍要保留完整流程：

- 舞蹈包卡片。
- 音乐。
- 海报。
- 全身检查。
- OK 手势或回退手势。
- 倒计时。
- 双角色跟舞。
- 评分和结算。

不能因为设备弱就砍掉整个游戏流程。

## 13.2 三种性能配置

| 配置 | 摄像头 | 姿态检测 | 3D 渲染 | 场景 |
|---|---|---|---|---|
| 高 | 1080p | 15 至 20 FPS | 30 至 60 FPS | 机器人 + 舞蹈房 + 阴影 |
| 平衡 | 720p | 12 至 15 FPS | 30 FPS | 机器人 + 简化舞蹈房 |
| 低 | 640×480 或 720p | 8 至 12 FPS | 20 至 30 FPS | 低模或骨架，无阴影和反射 |
| 极低 | 480p | 6 至 8 FPS | 15 至 20 FPS | 双骨架和 2D 判定条 |

## 13.3 低端模式限制

- 默认不加载 HDRI。
- 默认不开启镜面反射。
- 默认不开启透明粒子。
- 默认关闭阴影或使用廉价接触阴影。
- 贴图降到 512 或 1K。
- 骨架点数量和线宽降低。
- 一次只预加载当前动作包和当前角色。
- 控制缩略图缓存数量。
- 停止训练后释放未使用模型。
- 暂停时把渲染帧率降到 5 FPS，减少无意义功耗。
- 高级 3D 解析后端只在离线导入时运行，训练时关闭。

## 13.4 自动性能检测

首次启动执行轻量检测：

- GPU 名称和显存。
- WebGL 支持和渲染字符串。
- 摄像头默认分辨率。
- 可用内存。
- 磁盘读取速度。

评分后推荐配置，但允许用户覆盖。

## 13.5 自动降级

顺序：

1. 降低渲染分辨率。
2. 关闭粒子和反光。
3. 关闭阴影。
4. 降低模型贴图。
5. 机器人切低模。
6. 双角色切骨架和轮廓。
7. 降低姿态检测频率。
8. 关闭云端 TTS，改用本地语音或文字。

不能在游戏中途频繁切换档位导致画面闪烁。降级应有 3 至 5 秒的稳定窗口。

- `practice_history`：片段重练记录。
- `achievement_records`：奖励记录。
- `import_jobs`：导入任务状态和历史。

## 15. 安全、隐私和版权

### 15.1 音乐版权

- 用户导入的歌曲默认只在本机使用。
- 未经授权不随舞蹈包导出。
- 导出包如果包含音乐，必须有明确许可证。
- 比赛演示视频中的音乐需要单独说明来源。
- 支持无版权节拍音轨和用户自带音乐。

### 15.2 摄像头隐私

- 默认不保存训练录像。
- 默认不上传视频流。
- 海报默认使用视频帧时需要用户确认。
- 宿舍场景可以选择 3D 渲染海报，不暴露真人画面。
- 检测到室友时暂停准备或模糊非主要人物。

### 15.3 资产安全

- 动作包解压前校验大小和路径。
- 模型只允许指定格式。
- 不在运行时从随机 URL 下载模型。
- 云端只接收结构化摘要和 TTS 短句。
- 所有导入资产记录来源和许可证。

## 18. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| OK 手势误触 | 游戏未准备好就开始 | 全身检查先通过，手势保持 0.8 秒以上 |
| 手部模型兼容性差 | 无法使用 OK 手势 | 本地 MediaPipe/ONNX 双路线，保留举双手和空格回退 |
| 音乐版权不明 | 不能公开演示或导出 | 包内音乐必须带许可证，否则只保存本地引用 |
| 音乐和动作漂移 | 评分不可信 | 音乐作为主时钟，保存音频偏移 |
| 变速改变音高 | 用户体验不稳定 | 明确提示，后续预生成变速音频缓存 |
| 低端设备帧率不稳 | 判定抖动 | 姿态、渲染、手势分别限频和降级 |
| 卡片海报过大 | 大厅卡顿 | 主海报和缩略图分开存储 |
| 动作包损坏 | 应用崩溃 | 导入校验、哈希、隔离失败包 |
| 自动暂停频繁 | 用户烦躁 | 根据设备性能调整阈值，不逐帧暂停 |
| 评分过复杂 | 用户看不懂 | 只显示总分、连击和当前主问题，详情放结算页 |
| 多角色资源重复 | 显存不足 | 共享渲染器和纹理缓存，角色 LOD |
| 删除误操作 | 丢失训练成果 | 回收站、撤销和二次确认 |

## 19. 最终推荐路线

V3 实施顺序必须是：

1. 先做舞蹈包大厅和卡片，把“包”变成真正的产品资产。
2. 再做视频转换向导和海报，让用户可以创建包。
3. 然后接入音乐和节拍，保证跟舞有主时钟。
4. 接着做全身就位、OK 手势和倒计时，建立游戏开场仪式。
5. 再做实时 HUD、暂停、速度和评分。
6. 最后做结算、奖励、低端适配和发布硬化。

这套方案的核心不是增加按钮，而是形成完整闭环：

**选择包 → 看清包 → 准备好 → 确认开始 → 跟舞 → 看分数 → 重练 → 获得成长。**

它可以让 DanceMirror 从“能跑的 AI 项目”变成真正可演示、可玩、可比赛、可在普通设备运行的产品原型。
