## 0. 结论先行

V8 不再增加一套并列功能，而是冻结机器人指挥中心的系统级集成边界：

**只采集一次摄像头，只运行一次姿态推理，只保留一个机器人运行时写入者；语音负责改变意图和参数，实时模仿负责驱动身体，皮肤系统只改变外观，资源治理器负责在 6GB 显存设备上自动降级。**

V8 的最终体验是：

1. 用户进入机器人指挥中心。
2. 系统展示机器人、摄像头小窗、语音字幕、动作队列、质量指标和皮肤库。
3. 用户说“开始模仿我”，也可以直接点击“开始模仿”。
4. 系统校准全身、左右方向、安全区域和主要关节。
5. 机器人实时模仿摄像头前的人物。
6. 用户继续说“只模仿上半身”“减少抖动”“镜像我”“换赛博皮肤”“暂停”“继续”。
7. 所有语音命令都经过本地安全快速通道、确定性命令通道或云端 LLM 复杂指令通道。
8. 模仿、语音动作、舞蹈包、皮肤动画都通过统一的动作仲裁和角色运行时执行。
9. 性能不足时按固定顺序降级，不冻结界面，不让机器人乱跳，不把原始画面上传云端。

V8 要解决的不是单个功能，而是 V6 与 V7、V4 角色系统、V5 多模态系统和现有 `LiveTrainingWorker` 之间的集成冲突。

## 1. 当前项目差距与集成判断

### 1.1 当前项目已经具备

- `CameraSource` 摄像头读取。
- `YoloPoseEstimator` 2D 姿态推理。
- `normalize_frame` 坐标标准化。
- `BaselinePoseLifter` 保守深度。
- `retarget_frame` 从 COCO-17 到通用三点骨架。
- `SceneWidget` 与 Three.js 场景。
- `LiveTrainingWorker` 摄像头实时评分。
- `SpeechWorker` 语音播报队列。
- `CloudSpeechSynthesizer` 云端 TTS 接口。
- `CloudSummarizer` 结构化训练总结接口。
- `WorkerThreadController` QThread 生命周期控制。
- 现有 16 个左右的核心测试和 WebEngine 冒烟链路。

### 1.2 当前项目还没有

- 统一 `PoseFrameBus`。
- MediaPipe Hands 和 Face 适配器。
- Humanoid 骨骼四元数重定向。
- 可插拔角色运行时。
- 动作层与骨骼掩码。
- 机器人指挥中心控制状态机。
- 实时语音识别。
- LLM 意图规划和动作白名单。
- 皮肤包、材质槽和热切换。
- 6GB 显存资源治理器。
- 实时模仿的质量评估和自动降级。
- 单舞台、多角色、独立场景状态的对象模型。

### 1.3 现有关键实现限制

- 当前 Three.js 页面使用一个 `WebGLRenderer` 和左右裁剪视口，适合“参考动作对用户动作”的训练页，不适合直接承担机器人指挥中心的独立镜头、皮肤、动作层和单独角色状态。
- 当前 `LiveTrainingWorker` 同时负责采集、YOLO、评分和重定向。实时模仿若再启动一个 Worker，会重复调用 YOLO，导致 GPU 争抢、时间戳不一致和动作抖动。
- 当前 `retarget_frame` 主要输出关节位置，而不是完整 Humanoid 骨骼四元数。皮肤、IK、手部和面部映射需要更稳定的标准骨骼层。
- 当前低模人体由球体、圆柱和方块拼装。它适合训练反馈，不足以承载机器人、VRM、用户模型和皮肤系统。
- 当前没有动作层仲裁。语音动作、舞蹈包、实时模仿和皮肤动画如果直接写同一个骨架，会出现互相覆盖。
- 当前没有资源预算和皮肤缓存。连续换肤可能造成显存持续增长。

因此，实施顺序不能先做“好看的换肤按钮”，而必须先完成：

```text
标准姿态包
  -> 共享 Pose 总线
  -> Humanoid 骨骼重定向
  -> 单写入者 ActorRuntime
  -> 动作层仲裁
  -> 角色和皮肤槽
  -> 机器人指挥中心
  -> 语音混合控制
  -> 资源治理和发布硬化
```

### 1.4 V8 不做什么

- 不做云端连续视频上传。
- 不做人脸身份识别。
- 不做心理、疾病、敏感属性推断。
- 不让 LLM 直接输出关节旋转、骨骼矩阵或电机脉冲。
- 不在第一版恢复高精度 SMPL-X 真人网格。
- 不把蜘蛛侠、奥特曼等 IP 模型随项目分发。
- 不追求手机端、浏览器多人房间或云端实时推理。
- 不承诺 6GB 显存下同时开启全部最高质量模型。
- 不把 MediaPipe、YOLO、TTS、LLM、语音识别都放在主线程。

## 2. 用户主流程

### 2.1 首次进入机器人指挥中心

1. 页面显示机器人待机动作、摄像头未连接状态、语音未启动状态。
2. 系统检查摄像头、麦克风、YOLO 权重、Three.js 本地资源、TTS 配置和皮肤目录。
3. 缺失资源时给出可执行的修复提示，不阻塞设置页和历史页。
4. 用户选择模式：语音指挥、实时模仿、混合。
5. 默认推荐混合模式，但不会自动启用摄像头或麦克风。

### 2.2 开始实时模仿

1. 用户点击“开始模仿”或说“开始模仿我”。
2. 系统获取摄像头权限。
3. 摄像头小窗打开，先显示原始画面和骨架。
4. 系统检查全身可见、双脚可见、双手在安全区域、光照可用、只存在一个主要人物。
5. 系统完成主人物锁定和跟踪 ID 初始化。
6. 用户完成 A-Pose 或 T-Pose 校准。
7. 系统显示左右方向确认结果。
8. 页面执行 3、2、1 倒计时。
9. 机器人从待机状态平滑过渡到实时模仿层。
10. 底部显示模式、范围、FPS、延迟、覆盖率和安全状态。
11. 用户可随时说“停止模仿”“暂停”“恢复”“上半身”“换皮肤”。

### 2.3 语音和模仿混合

典型输入：

> 开始模仿我，只模仿上半身，减少一点抖动，然后换成赛博皮肤。

处理顺序：

1. “开始模仿我”切换模式。
2. “只模仿上半身”修改骨骼掩码，不重置动作。
3. “减少一点抖动”提高平滑强度，仅影响模仿层。
4. “换成赛博皮肤”进入皮肤切换事务，不改变当前姿态。
5. 高风险或低置信度命令触发澄清，不猜测。

### 2.4 摄像头丢失

1. 系统在 200 毫秒内停止接受新的模仿姿态。
2. 机器人冻结在当前安全姿态并平滑回归待机姿态。
3. 字幕显示“摄像头不可用，已进入安全保持”。
4. 如果摄像头在 2 秒内恢复，自动重新校准并恢复模仿。
5. 如果超过 5 秒未恢复，切回语音指挥模式。
6. 不无限预测用户动作，不继续播放错误的模仿结果。

### 2.5 皮肤切换

1. 用户点击皮肤卡片或说“换皮肤”。
2. 系统检查皮肤与当前模型、骨架和性能档位是否兼容。
3. 后台异步读取材质、贴图和配件。
4. 主线程和 Three.js 不等待文件读取。
5. 新资源准备完成后，原子替换材质槽。
6. 换肤过程中当前骨骼姿态、动作时间轴和语音字幕不重置。
7. 切换失败时保留旧皮肤并提示原因。
8. 无引用资源进入 LRU 缓存，缓存超限后释放。

### 3.1 单写入者原则

机器人最终姿态只能由一个 `ActorRuntime` 写入。其他模块只能提交“意图”：

- 语音提交 `MotionIntent`。
- 实时模仿提交 `ImitationPoseFrame`。
- 舞蹈包提交 `TimelineMotionIntent`。
- 皮肤提交 `SkinIntent`。
- 道具提交 `EffectIntent`。
- 安全模块提交 `SafetyIntent`。

`ActorRuntime` 是唯一可以：

- 修改根节点。
- 改变骨骼四元数。
- 融合动作层。
- 应用关节约束。
- 决定过渡和停止。
- 向 Three.js 写最终角色姿态。

### 3.2 单摄像头和单推理原则

同一条应用生命周期内，机器人指挥中心只允许存在一个主摄像头读取器和一个主动作推理器。

训练页如果同时打开，必须采用以下之一：

- 训练页暂停，机器人指挥中心独占摄像头。
- 两台物理摄像头分别绑定不同页面。
- 使用同一 `PoseFrameBus`，多个页面只订阅，不重复推理。

第一版优先采用“同一时刻一个页面使用摄像头”，降低宿舍环境和 6GB 显存下的复杂度。

### 3.3 纯数据跨线程原则

跨线程只传不可变纯数据：

- `PoseFramePacket`
- `QualitySnapshot`
- `MotionIntent`
- `CommandResult`
- `ActorPoseFrame`
- `SkinState`
- `RuntimeMetrics`

禁止子线程直接访问：

- `QWidget`
- `QPixmap`
- `QWebEngineView`
- Three.js 对象
- SQLite 连接对象
- 其他线程创建的 QObject

### 3.4 可回退原则

每个关键能力必须有回退路径：

| 能力 | 首选 | 回退 |
|---|---|---|
| 全身模仿 | Humanoid 骨骼重定向 | COCO-17 骨架显示 |
| 手部 | MediaPipe Hands 21 点 | 仅手腕方向或关闭 |
| 人脸 | Face 可见性和客观状态 | 只映射头部朝向 |
| 皮肤 | 完整 PBR 和配件 | 单色材质 |
| 角色 | GLB/VRM 模型 | 骨架角色 |
| 语音 | 云端流式 ASR | 本地 Vosk 或按钮 |
| 复杂指令 | 云端 LLM 规划 | 本地规则或澄清 |
| 评分 | 多模态融合 | 身体姿态评分 |
| TTS | 云端语音 | Windows SAPI |
| 场景 | Three.js | 原生骨架预览 |

## 4. 统一领域模型

### 4.1 运行模式

| 模式 | 说明 | 是否读取摄像头 | 是否接受语音 |
|---|---|---:|---:|
| `COMMAND` | 机器人由语音和面板命令驱动 | 否 | 是 |
| `IMITATION` | 机器人由摄像头姿态驱动 | 是 | 是，主要改变参数 |
| `HYBRID` | 模仿为主，语音控制范围、皮肤、镜头和安全 | 是 | 是 |
| `CALIBRATING` | 校准中，不接受舞蹈包和根运动 | 是 | 只接受取消和重置 |
| `SAFE_HOLD` | 安全保持，冻结姿态并等待恢复 | 可保留预览 | 只接受安全命令 |
| `SHUTTING_DOWN` | 正在释放资源 | 否 | 否 |

模式转换必须通过状态机，不允许按钮、Worker、定时器直接修改字符串。

### 4.2 控制来源优先级

数值越高，越晚覆盖低优先级结果：

| 优先级 | 来源 | 例子 |
|---:|---|---|
| 100 | 紧急安全 | 停止、重置、摄像头故障 |
| 80 | 用户明确暂停 | 暂停模仿、锁定当前姿态 |
| 60 | 实时模仿 | 身体、手部、头部、表情 |
| 40 | 确定性语音动作 | 走、跑、跳、转身、舞蹈包 |
| 20 | 面板设置 | 平滑、灵敏度、镜像、范围 |
| 10 | 皮肤和装饰 | 灯带、粒子、屏幕表情 |
| 0 | 待机动画 | 呼吸、眨眼、轻微摆动 |

优先级只决定“谁能覆盖谁”，不意味着高优先级一定直接切换。所有切换都要经过混合时间和骨骼掩码。

### 4.3 `PoseFramePacket`

字段规划：

| 字段 | 类型 | 说明 |
|---|---|---|
| `frame_id` | integer | 单调递增，用于去重 |
| `camera_timestamp_ns` | integer | 摄像头时间戳 |
| `monotonic_ns` | integer | 本地单调时钟 |
| `track_id` | integer | 主人物跟踪 ID |
| `bbox_xyxy` | array | 主人物框 |
| `keypoints_xy` | array | COCO-17 二维关键点 |
| `keypoints_xyz` | array | 保守三维关键点 |
| `joint_scores` | array | 每个关节置信度 |
| `image_size` | tuple | 输入图像宽高 |
| `body_orientation` | quaternion | 身体朝向估计 |
| `mirror_state` | boolean | 当前镜像语义 |
| `person_count` | integer | 画面人数 |
| `hand_summary` | object | 手部摘要，可为空 |
| `face_summary` | object | 人脸客观摘要，可为空 |
| `quality` | object | 覆盖率、抖动、缺失、延迟 |
| `schema_version` | string | 数据契约版本 |

JSON 示例：

```json
{
  "frame_id": 1842,
  "camera_timestamp_ns": 1789991200012000000,
  "monotonic_ns": 1789991200012500000,
  "track_id": 7,
  "bbox_xyxy": [0.18, 0.06, 0.82, 0.98],
  "keypoints_xy": [[0.51, 0.12], [0.47, 0.13]],
  "keypoints_xyz": [[0.02, 0.71, 0.08], [-0.05, 0.70, 0.05]],
  "joint_scores": [0.97, 0.94],
  "image_size": [1280, 720],
  "mirror_state": true,
  "person_count": 1,
  "quality": {
    "coverage": 0.94,
    "jitter": 0.03,
    "missing_frames": 0
  },
  "schema_version": "1.0"
}
```

实际数组长度必须由骨架规范严格确定，不能依赖可变列表隐式对齐。

### 4.5 `ActorPoseFrame`

最终写给角色运行时的姿态：

- `actor_id`
- `root_translation_m`
- `root_rotation`
- `bone_rotations`
- `bone_weights`
- `foot_lock_state`
- `hand_state`
- `face_state`
- `skin_slot_state`
- `timestamp_ns`
- `source_trace_id`

它与 `PoseFramePacket` 不同：

- `PoseFramePacket` 是摄像头识别结果。
- `ActorPoseFrame` 是经过重定向、融合、约束后的最终角色姿态。

## 5. ActorRuntime 与动作层

### 5.1 角色运行时对象

每个活跃角色拥有：

- `ActorDefinition`：模型、骨架契约、默认姿态、能力声明。
- `ActorState`：位置、旋转、可见性、生命周期。
- `MotionStack`：动作层栈。
- `AnimationGraph`：待机、走、跑、跳、舞蹈和过渡。
- `RetargetBinding`：源骨骼到目标骨骼的映射。
- `SkinBinding`：材质槽、配件槽和贴图缓存引用。
- `ConstraintSolver`：关节限制、脚锁和边界。
- `Metrics`：该角色的延迟和质量。

### 5.2 动作层

建议动作层：

| 层 | 作用 | 是否可持续 |
|---|---|---|
| Safety Layer | 安全保持、重置、冻结 | 是 |
| Base Idle Layer | 呼吸、待机、轻微摆动 | 是 |
| Locomotion Layer | 走、跑、转向 | 是 |
| Action Layer | 挥手、跳、转圈、单次动作 | 否 |
| Dance Layer | 舞蹈包时间轴 | 是 |
| Imitation Layer | 实时摄像头姿态 | 是 |
| Overlay Layer | 手部强调、头部补充、表情 | 是 |
| Effect Layer | 灯带、粒子、屏幕效果 | 是 |

### 5.3 骨骼掩码

模仿范围不能简单“开或关整段代码”，而要使用骨骼掩码：

```text
全身掩码：
  root + spine + arms + legs + hands + head + face

上半身掩码：
  spine + arms + hands + head + face

下半身掩码：
  root vertical + hips + legs + feet

手部掩码：
  wrists + fingers

头部掩码：
  neck + head

表情掩码：
  face channels
```

切换掩码时：

- 不重置动作时间轴。
- 不闪回默认姿态。
- 低层动作在失去掩码的区域平滑恢复。
- 新层在获得掩码的区域平滑进入。
- 用户可设置混合时间。

### 5.4 冲突规则

- 实时模仿开启全身时，语音“向前走”默认被拒绝，提示先关闭根节点模仿或切换为“原地模仿”。
- 实时模仿只控制上半身时，可以允许语音控制根运动。
- 舞蹈包和实时模仿不能同时控制相同骨骼。
- 皮肤动画不能改变骨骼旋转。
- 表情层可以被面部模仿覆盖，但不能覆盖安全状态。
- 紧急停止永远可以打断所有动作。

### 5.5 过渡策略

- 待机到模仿：200 至 350 毫秒淡入。
- 模仿到待机：250 至 500 毫秒淡出，避免突然站立。
- 姿态锁定：80 至 150 毫秒冻结。
- 关节约束：逐帧执行，不受混合时间影响。
- 皮肤切换：不参与动作混合。
- 摄像头丢失：先冻结，再回归安全姿态。

## 6. 实时模仿完整处理链

### 6.1 阶段总表

| 阶段 | 输入 | 输出 | 目标频率 | 线程 | 失败行为 |
|---|---|---|---:|---|---|
| 摄像头采集 | 摄像头 | 原始帧 | 30 FPS | Capture Worker | 进入安全保持 |
| 主人物跟踪 | 原始帧 | 主人物框 | 15 至 30 FPS | Pose Worker | 保持上一个 ID |
| YOLO Pose | 主人物区域 | COCO-17 | 12 至 18 FPS | Pose Worker | 短时预测 |
| 姿态融合 | YOLO 输出 | 标准姿态包 | 同 Pose FPS | Fusion Worker | 质量降级 |
| 手部 | 手腕 ROI | 21 点手势 | 5 至 10 FPS | Aux Worker | 关闭手指映射 |
| 人脸 | 头部 ROI | 客观特征 | 3 至 8 FPS | Aux Worker | 只保留头部朝向 |
| 校准 | 姿态包 | 人体比例 | 一次性 | Fusion Worker | 返回校准页 |
| 平滑 | 姿态序列 | 平滑姿态 | 每姿态帧 | Fusion Worker | 使用低通 |
| 重定向 | 源姿态 | Humanoid 旋转 | 每姿态帧 | Retarget Worker | 骨架回退 |
| 约束 | Humanoid 姿态 | 合法姿态 | 每姿态帧 | Actor Runtime | 冻结异常关节 |
| 插值 | 最近两个姿态 | 显示姿态 | 每渲染帧 | WebEngine | 保持最后合法姿态 |
| 渲染 | 显示姿态 | 3D 结果 | 30 至 60 FPS | WebEngine | 原生骨架回退 |

### 6.2 摄像头采集

- 默认请求 720p、30 FPS。
- 低端设备使用 640×480 或 720p、15 至 20 FPS。
- 读取线程只负责读取、时间戳和最新帧缓存。
- 队列长度固定，不保存无限历史。
- 一旦摄像头读取失败，连续 3 帧后触发安全保持。
- UI 预览使用缩放后的本地帧，不复制 10 份原图。

### 6.3 主人物检测

选择顺序：

1. 已有锁定 ID 且置信度足够。
2. 画面中最大、最稳定的人物。
3. 最靠近画面中心的人物。
4. 置信度最高的人物。

多人场景：

- 室友和其他人物进入隐私遮罩。
- 不把旁边人物的动作混入机器人。
- 主人物切换必须经过用户确认或明确的自动恢复规则。
- 跟踪 ID 变化不能直接造成骨骼瞬间跳变。

### 6.4 姿态推理

- YOLO 输入优先裁剪到主人物区域。
- 单帧只处理主人物。
- CUDA Tensor 必须在业务边界前转成 NumPy。
- 推理失败或超时时沿用上一个健康姿态包。
- 低置信度关节不能直接参与 IK。
- 每个关节保留置信度并传递到质量模块。

### 6.5 姿态标准化

- x 向右。
- y 向上。
- z 为深度。
- 原点在髋部中点。
- 姿态单位先以躯干长度为基准。
- 进入角色运行时前转换为米制。
- 根节点和身体局部姿态分离。
- 镜像只改变显示和根方向，不改变评分语义。

### 6.6 缺口修复

- 1 帧缺失：线性插值。
- 2 至 8 帧缺失：短时预测，最多 200 至 300 毫秒。
- 超过 300 毫秒：冻结最后稳定姿态。
- 超过 1 秒：降低质量等级。
- 超过 2 秒：安全保持。
- 不允许无限外推。
- 重新出现时使用 150 至 250 毫秒交叉淡化。

### 6.7 手部

- MediaPipe Hands 只在手腕 ROI 和附近区域运行。
- 输出 21 点、左右手和置信度。
- 手势识别使用本地规则，不使用云端。
- 首版重点支持打开手掌、握拳、OK、比心、指向和挥手。
- 目标角色无手指时使用替代反馈。
- 手部延迟不能超过全身动作 80 毫秒以上，超过时暂停手指层。

### 6.8 人脸

只保留客观特征：

- 可见性。
- 头部方向。
- 眨眼。
- 张嘴。
- 微笑程度。
- 面部遮挡。

不保留：

- 身份特征。
- 人脸识别模板。
- 原始人脸帧。
- 隐私敏感属性。
- 心理或情绪诊断结论。

表情默认关闭，用户主动开启后才运行。

### 6.9 校准

校准阶段：

1. 检查全身。
2. 检查双肩、双髋、双膝、双踝。
3. 检查双手。
4. 检查安全区域。
5. 用户完成 A-Pose。
6. 用户完成 T-Pose。
7. 校验左右手。
8. 校验身体朝向。
9. 记录比例和偏移。
10. 生成 `CalibrationProfile`。

保存内容只包括：

- 骨骼长度比例。
- 肩宽比例。
- 躯干比例。
- 腿长比例。
- 手臂比例。
- 初始朝向。
- 镜像状态。
- 根节点偏移。
- 摄像头延迟补偿。
- 创建时间和设备摘要。

## 7. PoseFrameBus 契约

### 7.1 总线职责

`PoseFrameBus` 只负责：

- 接收一个生产者的姿态包。
- 维护帧号和时钟。
- 向多个订阅者分发不可变快照。
- 执行每个订阅者的背压策略。
- 记录丢弃和延迟指标。

它不负责：

- 评分。
- 重定向。
- 渲染。
- 语音解析。
- 皮肤切换。
- 数据库写入。

### 7.2 订阅者

| 订阅者 | 消费频率 | 背压策略 | 输出 |
|---|---|---|---|
| `ScoringSubscriber` | 每个新姿态帧 | 最多等一帧，超时跳过 | 评分 |
| `ImitationSubscriber` | 最新帧优先 | 丢旧保新 | 模仿姿态 |
| `QualitySubscriber` | 每帧或聚合 | 只保留统计值 | 质量快照 |
| `PreviewSubscriber` | UI 刷新频率 | 丢旧保新 | 骨架叠加 |
| `RecordingSubscriber` | 用户主动开启 | 固定长度队列 | 本地动作序列 |
| `ActionRecognitionSubscriber` | 后续版本 | 独立队列 | 动作标签 |

### 7.3 时钟

- 摄像头时间戳来自采集源。
- 单调时钟用于延迟和排序。
- Three.js 使用单调时间轴插值。
- 音乐时钟只用于舞蹈包，不用来驱动摄像头姿态。
- 所有跨模块日志显示 `trace_id` 和 `frame_id`。

### 7.4 丢弃规则

- 新帧到达时，旧帧未消费则标记丢弃。
- 每个订阅者单独记录丢弃理由。
- 质量面板显示“推理慢”还是“渲染慢”。
- 不允许队列无限增长。
- 不允许因为 UI 阻塞让摄像头线程卡死。

## 8. 机器人指挥中心和语音仲裁

### 8.1 三条语音通道

| 通道 | 延迟目标 | 示例 | 是否依赖云端 |
|---|---:|---|---:|
| 安全快速通道 | 小于 150 ms | 停止、暂停、取消、回原位 | 否 |
| 确定性命令通道 | 小于 300 ms | 上半身、镜像、换皮肤、速度 | 否 |
| LLM 复杂指令通道 | 0.8 至 3 s | 多步任务、依赖顺序、澄清 | 可配置 |

紧急命令不等待 LLM，不允许因为网络问题失效。

### 8.2 语音完整链路

```text
麦克风
  -> 音频预处理
  -> VAD
  -> 临时字幕
  -> ASR
  -> 最终字幕
  -> 文本清理
  -> 安全快速匹配
  -> 本地确定性解析
  -> 可选 LLM 规划
  -> 动作白名单
  -> 参数范围校验
  -> 冲突和依赖校验
  -> CommandArbiter
  -> ActorRuntime
  -> 字幕和 TTS
```

### 8.3 本地确定性命令

首批本地命令：

- 开始、停止、暂停、继续模仿。
- 全身、上半身、下半身、手部、头部、表情。
- 镜像开、镜像关。
- 更平滑、更灵敏。
- 上一个、下一个、默认、随机皮肤。
- 暂停、继续、停止舞蹈。
- 镜头拉近、拉远、重置。
- 紧急停止、重置姿态。

### 8.4 LLM 规划边界

LLM 可以：

- 拆分多步命令。
- 选择白名单动作。
- 生成顺序和依赖。
- 选择舞蹈包 ID。
- 生成 TTS 回复。
- 请求澄清。

LLM 不可以：

- 输出骨骼旋转。
- 输出关节矩阵。
- 发明动作名称。
- 发明时间段。
- 修改评分。
- 绕过安全限制。
- 批准超限速度、距离和场景边界。
- 直接调用文件或系统命令。

### 8.5 CommandArbiter

仲裁步骤：

1. 验证意图是否在白名单。
2. 验证参数范围。
3. 验证角色是否存在。
4. 验证动作是否与当前模式冲突。
5. 检查动作队列和依赖。
6. 分配优先级。
7. 决定立即执行、排队、替换、拒绝或澄清。
8. 写入审计日志，但隐藏敏感内容。
9. 返回 `CommandResult`。

### 8.6 冲突示例

| 当前状态 | 新命令 | 决策 |
|---|---|---|
| 全身模仿中 | 向前走 | 拒绝，提示先关闭根节点模仿 |
| 全身模仿中 | 只模仿上半身 | 立即改变掩码 |
| 上半身模仿中 | 向前走 | 允许，根运动由动作层控制 |
| 舞蹈播放中 | 换皮肤 | 立即执行，不打断舞蹈 |
| 舞蹈播放中 | 开始模仿 | 先暂停舞蹈或请求确认 |
| 安全保持中 | 换皮肤 | 允许皮肤事务，但不恢复动作 |
| 摄像头丢失 | 继续模仿 | 拒绝，要求先恢复摄像头 |
| 云端 LLM 超时 | 停止 | 本地通道已执行，不受影响 |

### 8.7 字幕结构

每一行至少包括：

- 时间。
- 文本类型：用户、临时 ASR、最终 ASR、意图、机器人回复、系统状态。
- 原文。
- 清理后文本。
- 命令结果。
- 错误原因。
- 隐私遮罩状态。

字幕不显示 API Key、完整请求体、内部模型输出或敏感路径。

## 9. 重定向与关节约束

### 9.1 统一 Humanoid 契约

标准骨骼名称建议：

```text
root
hips
spine
chest
neck
head
left_shoulder
left_upper_arm
left_forearm
left_hand
right_shoulder
right_upper_arm
right_forearm
right_hand
left_upper_leg
left_lower_leg
left_foot
right_upper_leg
right_lower_leg
right_foot
```

手指骨骼作为可选扩展，不要求所有角色支持。

### 9.2 重定向步骤

1. 读取源骨骼相对旋转。
2. 转换源坐标系到目标坐标系。
3. 应用目标角色初始姿态。
4. 调整骨架比例。
5. 计算目标关节四元数。
6. 应用关节限制。
7. 处理根节点。
8. 应用脚锁。
9. 应用手部和表情层。
10. 输出 `ActorPoseFrame`。

### 9.3 关节限制

- 肘部禁止反向折叠。
- 膝盖禁止反向折叠。
- 肩部限制极限旋转。
- 脊柱限制异常弯折。
- 头颈限制极端角度。
- 手腕限制翻转。
- 硬质机甲角色使用更严格限制。
- 置信度低时限制强度提高，而不是直接放大噪声。

### 9.4 脚底稳定性

- 首版允许轻量脚锁。
- 进入接触阶段时锁定脚底。
- 离开接触阶段时释放脚锁。
- 根节点运动必须经过舞台边界和速度限制。
- 低端模式关闭复杂 IK，只使用位置约束。
- 不允许脚底持续滑动。

### 9.5 表情映射

- 张嘴映射屏幕嘴型。
- 微笑映射发光或表情纹理。
- 眨眼映射屏幕灯光。
- 转头只驱动头颈骨骼。
- 无面部角色映射到头顶灯、胸灯或眼睛灯。
- 不重建真实人脸。

## 10. 皮肤系统

### 10.1 皮肤不是重新加载角色

皮肤系统只操作可视化槽：

| 槽 | 内容 | 是否影响骨骼 |
|---|---|---:|
| Body Material | 主色、金属度、粗糙度、发光 | 否 |
| Head Material | 头盔、屏幕、眼睛 | 否 |
| Hand Material | 手掌和手指颜色 | 否 |
| Texture Set | 基础色、法线、粗糙、发光 | 否 |
| Accessory Set | 披风、背包、肩甲、尾迹 | 否 |
| Screen Face | 表情和嘴型 | 否 |
| Effect Set | 灯带、粒子、脉冲 | 否 |

换肤不得重新创建骨架，不得重置动作时间轴，不得清空当前模仿姿态。

### 10.2 皮肤包

```text
cyber_neon.dskin
  manifest.json
  license.json
  checksums.json
  preview.jpg
  materials.json
  effects.json
  textures/
  accessories/
```

限制：

- 只允许相对路径。
- 禁止远程 URL。
- 禁止脚本和可执行文件。
- 禁止路径穿越。
- 限制压缩包大小和解压后大小。
- 限制单张纹理尺寸。
- 校验文件哈希。
- 许可证不清晰时禁止导出。
- 用户导入的 IP 模型只在本地使用。

### 10.3 皮肤切换事务

```text
SkinIntent
  -> 检查角色兼容
  -> 检查骨架契约
  -> 检查性能档位
  -> 检查许可证
  -> 异步读取和校验
  -> 编译材质变体
  -> 预备纹理和配件
  -> 创建临时 SkinBinding
  -> 原子交换
  -> 淡入新皮肤
  -> 释放无引用资源
```

失败时：

- 保留旧 `SkinBinding`。
- 不改变角色姿态。
- 不改变动作时间轴。
- 显示失败原因。
- 记录一次错误指标。
- 不把失败资源放入主缓存。

### 10.4 资源缓存

- 材质变体按设备性能档位缓存。
- 纹理按角色和皮肤 ID 缓存。
- 配件单独引用计数。
- 最近最少使用资源优先释放。
- 当前皮肤和下一候选皮肤不释放。
- 切换 20 次后进行稳定性和显存对比。
- 缓存超限时不影响主线程。

### 10.5 动态皮肤预算

允许：

- 节拍灯带。
- 成功脉冲。
- 错误红灯。
- 说话嘴型。
- 模仿手部状态。
- 连接状态指示灯。

限制：

- 粒子数量有限。
- 透明层数量有限。
- 低端设备关闭粒子。
- 低端设备关闭透明和复杂反射。
- 性能下降超过阈值时优先关闭皮肤动画，而不是关闭姿态推理。

### 10.6 皮肤命令

本地支持：

- 换皮肤。
- 上一个、下一个、随机、默认皮肤。
- 把灯调成蓝色。
- 增强发光。
- 降低金属感。
- 只换颜色。
- 锁定皮肤组合。
- 保存自定义变体。

LLM 只能映射到上述白名单，不得动态生成材质代码。

## 11. 场景、镜头与角色显示

### 11.1 场景单位

- 1 Three.js 单位等于 1 米。
- 角色根节点位于舞台地面中心。
- 相机使用米制近远裁剪。
- 角色根节点带独立缩放。
- 骨架数据先归一化，再乘角色比例进入场景。
- 舞台边界由场景配置提供，不在各个动作模块中硬编码。

### 11.2 角色状态

- 当前角色 ID。
- 当前皮肤 ID。
- 当前动作层。
- 当前姿态来源。
- 当前根节点位置。
- 当前脚锁状态。

## 13. 线程、生命周期和 WebEngine 桥

### 13.1 线程职责

| 线程/对象 | 负责 | 不负责 |
|---|---|---|
| 主线程 | UI、信号、状态机入口、轻量调度 | YOLO、网络、文件哈希 |
| Capture Worker | 摄像头读取、时间戳、最新帧 | UI、模型推理 |
| Pose Worker | YOLO、主人物检测 | 评分、渲染 |
| Aux Worker | Hands、Face 低频 | 骨骼写值 |
| Fusion Worker | 标准化、质量、缺口、平滑 | QWidget |
| Retarget Worker | Humanoid 重定向 | 网络和 UI |
| ASR Worker | 音频、VAD、识别、字幕事件 | 直接执行动作 |
| Intent Worker | 规则、LLM、校验、规划 | 直接写骨骼 |
| Skin Worker | 读取、哈希、材质准备 | 替换 WebEngine 对象 |
| Storage Worker | SQLite、校准、日志 | UI 模型 |
| WebEngine | 最终角色姿态、材质、场景 | 访问 Python QWidget |

### 13.2 QThread 生命周期

每个 Worker 必须：

- 有 `stop()`。
- 有独立异常出口。
- 由界面或控制器持有引用。
- 关闭时执行停止、退出、等待、释放。
- 等待超时后记录错误，不强制销毁正在使用的对象。
- 不允许在 `closeEvent` 后继续 emit UI 信号。

### 13.3 WebEngine 写入

- Python 到 WebEngine 只发送纯 JSON 或受限命令。
- 不拼接未经转义的字符串。
- WebEngine 对象只在主线程访问。
- 角色姿态每帧只写一次。
- 皮肤切换使用独立命令通道。
- 渲染脚本失败时切回原生骨架。
- 页面卸载前停止动画循环和材质资源。

### 13.4 启动顺序

1. 加载设置和路径。
2. 初始化日志和指标。
3. 初始化主窗口。
4. 启动语音播报 Worker。
5. 启动资源治理器。
6. 加载角色和默认皮肤索引。
7. 用户进入机器人指挥中心。
8. 按需启动摄像头、Pose、ASR 和 SceneRuntime。

### 13.5 停止顺序

1. 停止接受新命令。
2. 停止模仿和动作队列。
3. 停止摄像头采集。
4. 停止 Pose、Hands、Face 和 ASR Worker。
5. 停止重定向和融合。
6. 停止 WebEngine 动画循环。
7. 保存必要设置和校准。
8. 释放皮肤、纹理和角色资源。
9. 停止剩余 Worker。
10. 清理引用。

## 14. 性能与资源治理

### 14.1 性能目标

目标设备为 RTX 3060 Laptop 6GB，720p 摄像头，混合模式：

| 指标 | 目标 |
|---|---:|
| 摄像头 FPS | 30 |
| YOLO Pose FPS | 12 至 18 |
| Hands FPS | 5 至 10 |
| Face FPS | 3 至 8，可关闭 |
| 渲染 FPS | 30 至 60 |
| 平均端到端延迟 | 100 至 160 ms |
| 95% 端到端延迟 | 小于 180 ms |
| 紧急语音命令 | 小于 150 ms |
| 换肤无姿态中断 | 大于 99% |
| 连续运行 | 30 分钟 |
| 显存余量 | 目标大于 0.8 GB |

这些是工程目标，不是未经验证的保证。最终数值必须通过目标机器实测。

### 14.2 资源预算

在 6GB 显存设备上，按“预算上限”管理：

| 资源 | 目标上限 | 说明 |
|---|---:|---|
| 系统与桌面占用 | 0.8 至 1.2 GB | 因驱动和桌面环境变化 |
| Qt WebEngine 与 Three.js | 0.6 至 1.1 GB | 取决于角色和皮肤 |
| YOLO Pose | 0.7 至 1.4 GB | 取决于模型和批大小 |
| 纹理与材质缓存 | 0.3 至 0.7 GB | 受 LRU 限制 |
| 临时缓冲 | 0.2 至 0.4 GB | 图像和姿态包 |
| 安全余量 | 大于 0.8 GB | 防止 OOM 和驱动抖动 |

如果实测超过上限，优先降低皮肤纹理和角色复杂度，不降低安全命令和基础姿态质量。

### 14.3 性能档位

| 档位 | 摄像头 | Pose | Hands | Face | 角色 | 皮肤 |
|---|---|---|---|---|---|---|
| P0 高质量 | 720p | 15 至 18 FPS | 8 至 10 FPS | 5 至 8 FPS | 完整 GLB | PBR + 特效 |
| P1 平衡 | 720p | 12 至 15 FPS | 5 至 8 FPS | 3 至 5 FPS | 完整 GLB | 基础 PBR |
| P2 节能 | 640×480 | 8 至 12 FPS | 3 至 5 FPS | 关闭 | 简化模型 | 单色材质 |
| P3 安全模式 | 640×480 | 8 FPS | 关闭 | 关闭 | 骨架回退 | 无贴图 |

### 14.4 降级顺序

1. 降低动态皮肤粒子。
2. 降低纹理尺寸。
3. 关闭透明和复杂反射。
4. 降低 Face 频率。
5. 关闭手指映射。
6. 降低 Hands 频率。
7. 降低 YOLO 频率。
8. 关闭根节点移动。
9. 切换简化角色。
10. 切换骨架回退。
11. 冻结为安全姿态。
12. 切回语音指挥模式。

### 14.5 防抖动降级

- 进入低档位需要持续超过阈值。
- 恢复高档位需要连续稳定一段时间。
- 使用滞回阈值避免频繁升降。
- 一次只降一级。
- 紧急 OOM 可以跳级。
- 所有档位变化写入指标和字幕。

### 14.6 资源治理触发项

- VRAM 接近安全线。
- GPU 推理时间连续超限。
- 渲染 FPS 连续低于目标。
- 姿态队列持续积压。
- WebEngine 写入耗时升高。
- 皮肤缓存超限。
- CPU 或 RAM 异常增长。
- 连续运行出现缓慢泄漏。

## 15. 隐私、安全与许可证

### 15.1 摄像头

- 原始视频本地处理。
- 默认不上传。
- 默认不保存录像。
- 用户主动开启后才保存。
- 宿舍模式模糊其他人物和背景。
- 关闭摄像头后立即停止采集。

### 15.2 人脸

- 不做身份识别。
- 不保存人脸模板。
- 不保存连续面部关键点。
- 表情默认关闭。
- 只显示客观可见性、转向、眨眼、张嘴和微笑。
- 不输出心理、疾病或敏感属性结论。

### 15.3 音频

- 安全命令本地处理。
- 云端 ASR 必须显式启用。
- 音频日志默认不保存。
- 字幕只保存在会话内。
- TTS 失败不影响动作执行。
- 回声和自播报需要抑制，避免机器人听到自己的声音。

### 15.4 云端 LLM

- 只发送结构化文本和必要参数。
- 不发送原始视频。
- 不发送面部关键点。
- 不发送完整音频。
- 不发送 API Key。
- 响应必须符合 JSON Schema。
- 超时、非法 JSON 和未知动作都要安全拒绝。

### 15.5 皮肤和模型许可证

- 每个资源记录来源和许可证。
- CC0 资源优先作为默认分发资源。
- 用户导入 IP 模型只保存在本地。
- 不把用户导入模型打包进舞蹈包。
- 不默认上传用户模型。
- 皮肤包不能执行脚本。
- 导出前检查许可证策略。

## 20. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 重复运行 YOLO | GPU 过载、动作不同步 | 单 PoseFrameBus |
| 多个模块写骨骼 | 动作跳变、互相覆盖 | 单 ActorRuntime 写者 |
| 换肤重置姿态 | 模仿中断 | 材质槽事务，不重建骨架 |
| 皮肤资源泄漏 | 显存持续增长 | 引用计数和 LRU |
| 手部模型抢占 GPU | 全身姿态掉帧 | ROI、低频、CPU 优先 |
| 人脸隐私敏感 | 用户拒绝 | 默认关闭、本地处理、不持久化 |
| LLM 幻觉动作 | 执行未知行为 | 枚举白名单和二次校验 |
| 云端超时 | 语音控制卡顿 | 本地安全快速通道 |
| 摄像头构图错误 | 左右和比例错误 | 校准和方向确认 |
| 低端设备不足 | 卡顿和崩溃 | 性能档位和降级阶梯 |
| 角色比例不同 | 动作不对齐 | Humanoid 契约和重定向 |
| 皮肤不兼容 | 材质错误或黑模 | 槽绑定和兼容检查 |
| WebEngine 卡死 | 界面冻结 | 独立渲染桥和原生回退 |
| IP 资产分发 | 许可证风险 | 用户本地导入，不随项目打包 |

满足以下条件才算 V8 集成完成：

- 机器人指挥中心可以启动实时模仿。
- 摄像头只被一个采集模块读取。
- 姿态只被一个主推理模块计算。
- 语音、模仿、舞蹈和皮肤不会各自启动 YOLO。
- 机器人最终姿态只有一个运行时写入。
- 用户可以用语音开始、暂停、停止模仿。
- 用户可以切换全身、上半身、手部、头部和表情范围。
- 用户可以调整平滑、灵敏度和镜像。
- 摄像头丢失时有安全保持。
- 手部和人脸模块可以独立关闭。
- 皮肤可以在模仿中热切换。
- 换肤失败可以回退。
- LLM 只能输出白名单意图。
- 紧急命令不依赖云端。
- 6GB 显存下可以稳定运行目标配置。
- 性能不足时自动降级，不冻结 UI。
- 默认不上传原始图像和音频。
- 角色、皮肤和动作资源许可证清晰。
- 训练页、机器人指挥中心和历史页互不破坏。
- 所有 Worker 有明确停止和释放路径。
- 端到端测试、性能测试和发布检查通过。

最终目标不是“又增加一个页面”，而是形成一套真正可扩展的桌面多模态机器人系统：

**语音是控制层，摄像头是感知层，Pose 总线是数据层，角色运行时是执行层，皮肤是表现层，资源治理器是稳定性保障。**
